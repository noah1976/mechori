# MECHORI UI Terminology

## 方針

- `CURRENT`: コードと画面にはJournal、クイック記録、詳しい記録、フィード等の表現が混在する。
- `PROPOSED`: 日常利用者には「愛車の記録」を中心語にする。
- `NEEDS_DECISION`: 設定・管理・将来Professionalで専門語をどこまで表示するかは別途決める。

| 対象 | 推奨する表現 | 使用を避ける表現 | 使用する場面 | 理由 |
| --- | --- | --- | --- | --- |
| 全般的な投稿 | 愛車の記録、記録 | 投稿、Journal | 一覧、詳細、保存後 | 思い出・日常・整備を同じ時間軸に置ける |
| 作成操作 | 記録を残す | 投稿する、作成するだけ | 主ボタン、空状態 | 行為と愛車の関係が伝わる |
| 日常・思い出 | 愛車の記録 | 日記、SNS投稿 | お題、フィード、入力補助 | 私的すぎず、整備記録ともつながる |
| 構造化した作業 | 整備記録 | 詳細投稿、サービス記録 | 作業・部品・費用・結果を扱う時だけ | 事実性と後日の再利用を示せる |
| 入力モード | 記録を残す | クイック記録、詳しい記録 | 入口、主画面 | 内部モードを選ばせない。必要なら画面内で段階的に詳細を開く |

| 自分の車両一覧 | マイガレージ | プロフィール、マイページ | 下部ナビ、Garage | 車両と履歴が主役だと伝わる |
| 他人のプロフィール | ○○さんのガレージ | 公開プロフィール、ユーザー詳細 | 人物ページの見出し | 人と所有車両の関係が自然に分かる |
| 個別車両 | 愛車ページ | 車両プロフィール、vehicle | 車名を見せる画面 | 愛着と履歴の主役を示せる |
| 自分の入口 | ホーム | ダッシュボード | ログイン後の最初の画面 | SaaS管理画面の印象を避ける |
| フォロー中の一覧 | みんなの記録 | フィード | ホーム内の見出し | 内容が伝わりやすい。内部コードにはfeedを残してよい |
| フォロー | フォローする | 購読する、接続する | 人・車両の操作 | 一般的で理解しやすい |
| 公開範囲 | 見せる相手 | audience、公開レベル | 入力・設定 | 「誰に見えるか」を先に伝える |
| α内共有 | MECHORIの参加者に見せる | 公開 | αでの公開範囲選択 | 一般Web公開との誤解を防ぐ |
| 通知 | お知らせ | activity、イベント | P-073以降 | 行動を促すが圧迫感が少ない |
| 下書き | 書きかけの記録 | draft | 復元・失敗時 | 状態が直感的に分かる |
| 整備の実施者 | 作業した人・場所 | performer、attribution | 整備・修理・点検の記録 | DIYとお店・工場を短く区別する |
| 実在する整備拠点 | お店・工場 | Garage、Professional Organization | Record入力、Provider選択 | 個人のマイガレージと混同しない |
| Professional管理主体 | 事業者 | 工場アカウント、Garage | 事業者スペース、管理画面 | 個人アカウントとOrganizationを分ける |

## 現行で統一が難しい箇所

- `CURRENT`: ルート名、コンポーネント名、データ型に`journal`、`quick-event`、`service-brief`が残る。これは実装内部に留め、利用者向け文言だけを段階的に置換する。
- `CURRENT`: 「公開」が記録本文、写真、車両、α参加者内共有で異なる意味になり得る。入力時は「見せる相手」と具体的な範囲を併記する必要がある。
- `CURRENT`: `Vehicle Experience`、`Experience Entry`、`Evidence`はProduct / Architecture内部語であり、一般利用者向け画面では「愛車の記録」「記録の詳細」「続きを残す」へ翻訳する。
- `NEEDS_DECISION`: 「みんなの記録」をフォロー中だけに使うか、参加者全体まで含めるか。
