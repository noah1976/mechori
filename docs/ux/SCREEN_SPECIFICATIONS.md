# MECHORI Screen Specifications

## 文書の前提

- `CURRENT`: 現行コード・ルートから再利用できるもの
- `PROPOSED`: 実装前の情報構造と操作階層
- `NEEDS_DECISION`: プロダクトオーナーの判断が必要な事項
- 具体的なCSS、完成ビジュアル、実際の操作感は本書で確定しない。人間による画面確認が必要である。

## 1. ログイン後ホーム

- **画面の目的**: 自分の愛車の現在地と、関係する記録の変化を短時間で把握する。
- **対象ユーザー／来る理由**: 再訪したオーナー。愛車のこと、フォロー中の人・クルマの変化を見たい。
- **最もしてほしい操作／主ボタン**: 「記録を残す」。
- **副操作**: 自分の愛車を開く、みんなの記録を開く、人・クルマを探す。
- **情報の表示順**: 自分の愛車の要約 → 再開できる下書き → みんなの記録 → 探す導線。
- **表示してはいけないもの**: 管理操作、内部モード名、すべての設定、長い整備入力。
- **初回／空状態**: 車両未登録なら「最初の愛車を登録」。フォロー・記録がないなら、愛車の記録または人・クルマ検索へ進める。
- **読み込み／エラー**: 愛車要約を先に表示し、取得失敗した領域だけ再試行できる。画面全体を永久ローディングにしない。
- **保存成功状態**: 完了画面から戻る場合、追加された記録を自分の愛車要約で確認できる。
- **スマートフォン／アクセシビリティ**: 主ボタンは親指で届く位置。更新状態を色だけで伝えず、見出しと件数を使う。
- **戻る操作**: 下部ナビゲーションの他領域へ戻る。深いリンクではブラウザ戻るで直前へ。
- **関連する計測イベント**: `home_opened`、`record_entry_opened`、`draft_resume_selected`、`feed_record_opened`。
- **CURRENTで再利用できるもの**: ホーム、フィード、Garage要約、下書き、既存の作成導線。P-074試験実装では4項目ナビとメニューを共通シェルから再利用する。
- **NEEDS_DECISION**: ホームをフォロー中の記録中心にするか、愛車中心にするか。推奨は愛車要約を先頭、フォロー中の記録を次に置く。

## 2. マイガレージ

- **画面の目的**: 自分が今乗っている車両と、これまでの愛車を整理し、各車両の歴史へ入る。
- **対象ユーザー／来る理由**: 自分の愛車を見返す、別の愛車を選ぶ、車両を追加する。
- **最もしてほしい操作／主ボタン**: 「愛車を開く」。車両未登録時は「愛車を登録」。
- **副操作**: 記録を残す、車両を追加、過去車を見る、プロフィール設定。
- **情報の表示順**: 現在のガレージ → 現在車のカード → これまでの愛車 → 車両追加。
- **表示してはいけないもの**: 他人の候補、運用管理、車種マスタの内部状態。
- **初回／空状態**: 「まだ愛車が登録されていません」では終わらず、写真なし・年式不明でも始められることを示す。
- **読み込み／エラー**: 車両一覧と車両別の補助情報を分離して表示し、失敗した区画だけ再試行可能にする。
- **保存成功状態**: 車両登録・記録保存後、その車両を先頭または明確な位置に表示する。
- **スマートフォン／アクセシビリティ**: 現在車と過去車を見出しで分け、カード全体を多重リンクにしない。
- **戻る操作**: 下部ナビでホームへ。車両ページからはGarageへ。
- **関連する計測イベント**: `garage_opened`、`vehicle_selected`、`vehicle_add_started`、`record_entry_opened`。
- **CURRENTで再利用できるもの**: `/garage`、現在車・過去車の表示、車両追加、Garage内作成導線。記録作成は共通FABから既存ルートへ接続する。
- **NEEDS_DECISION**: 複数台所有時に「代表の愛車」を固定するか。推奨は最終閲覧車両または明示選択で、勝手に代表を決めない。

## 3. 他人のガレージ

- **画面の目的**: ある人が大切にしている公開車両と記録を知り、必要なら人または車両をフォローする。
- **対象ユーザー／来る理由**: 投稿者の背景を知る、同車種・別車種のオーナーを見つける。
- **最もしてほしい操作／主ボタン**: 「この人をフォロー」。
- **副操作**: 各愛車を開く、特定の愛車だけをフォロー、記録を開く。
- **情報の表示順**: 表示名・`@username` → 短いbio → 公開中の愛車 → 最近の公開記録。
- **表示してはいけないもの**: 内部UUID、非公開車両、運用属性、他人の非公開履歴。
- **初回／空状態**: 公開車両がない場合は、人をフォローする理由を強制しない。安全な説明だけを表示する。
- **読み込み／エラー**: 権限外・退会・ブロック時はプロフィール情報を漏らさず、探すへ戻れる。
- **保存成功状態**: フォロー後、人と車両のどちらをフォローしたかを短く返す。
- **スマートフォン／アクセシビリティ**: 人フォローと車両フォローを別ボタンにし、対象を読み上げで区別する。
- **戻る操作**: 記録詳細または探すへ。
- **関連する計測イベント**: `owner_garage_opened`、`user_follow_changed`、`vehicle_follow_changed`。
- **CURRENTで再利用できるもの**: `/profile/[id]`、プロフィール画像、公開車両、フォロー部品。
- **NEEDS_DECISION**: 「公開プロフィール」を画面名として残すか。推奨は「○○さんのガレージ」。

## 4. 愛車ページ

- **画面の目的**: 一台の車両の現在地、基本情報、時間軸を一つの文脈で見せる。
- **対象ユーザー／来る理由**: 自分の愛車を振り返る、他人の愛車を知る、次の記録を残す。
- **最もしてほしい操作／主ボタン**: 所有者なら「記録を残す」、閲覧者なら「このクルマをフォロー」。
- **副操作**: 車両情報を見る、記録を開く、所有者のGarageを開く、編集（所有者のみ）。
- **情報の表示順**: 車両写真または文字情報 → 車名・愛称・所有状況 → 直近の記録 → タイムライン → 補助情報。
- **表示してはいけないもの**: 内部車両ID、車種マスタの確度・管理状態、不要な仕様入力欄。
- **初回／空状態**: 記録なしなら「この愛車の最初の記録を残す」。写真なしは文字情報を主役にする。
- **読み込み／エラー**: 車両の基本情報を先に、写真・記録を後から読み込んでも理解できる構成にする。
- **保存成功状態**: 新しい記録の位置と、タイムラインが一件育ったことを見せる。
- **スマートフォン／アクセシビリティ**: 車両写真は内容を隠さず、画像なしでも情報階層が崩れない。時系列は日付精度を誤って補完しない。
- **戻る操作**: 自分ならGarage、他人ならその人のGarageまたは記録詳細。
- **関連する計測イベント**: `vehicle_page_opened`、`timeline_opened`、`record_entry_opened`、`vehicle_follow_changed`。
- **CURRENTで再利用できるもの**: `/garage/[vehicleId]`、車両カード、タイムライン、フォロー、編集導線。
- **NEEDS_DECISION**: 愛車ページとタイムラインを同一画面にするか。推奨は同一ページ内に要約と時間軸を置く。

## 5. 記録開始

- **画面の目的**: 記録の方法ではなく、残したい愛車の出来事から自然に入力へ入る。
- **対象ユーザー／来る理由**: 今日の写真、ドライブ、故障、整備、思い出を残したい。
- **最もしてほしい操作／主ボタン**: 車両を確認して「記録を残す」。
- **副操作**: お題を選ぶ、自由に書く、車両を変更する、下書きを復元する。
- **情報の表示順**: 選択中の愛車 → 「今日は、愛車のどんな記録を残しますか？」 → お題 → 自由に書く。
- **表示してはいけないもの**: クイック記録／詳しい記録というモード選択、Journalという内部名、Service Brief。
- **初回／空状態**: 車両がなければ愛車登録へ。お題を選ばなくても自由に開始できる。
- **読み込み／エラー**: 下書き確認はフォームが空の時だけ表示し、既存入力を勝手に上書きしない。
- **保存成功状態**: 入力画面ではなく完了画面へ移り、同じ内容を再送信しない。
- **スマートフォン／アクセシビリティ**: お題は最大5件、横スクロールに依存せず、タップ対象を十分に大きくする。
- **戻る操作**: 元のホーム、Garage、愛車ページへ戻る。下書きは保存する。
- **関連する計測イベント**: `record_entry_opened`、`record_prompt_selected`、`free_record_selected`、`draft_prompt_seen`。
- **CURRENTで再利用できるもの**: 既存のお題定義、`/journal/new`、車両別作成、下書き保存。
- **NEEDS_DECISION**: お題とカテゴリをどちらから見せるか。推奨はお題を先、カテゴリは入力途中の任意補助。

## 6. 記録入力

- **画面の目的**: 最小の一言から開始し、必要な情報だけを追加できる。
- **対象ユーザー／来る理由**: 愛車に起きたことを忘れる前に残したい。
- **最もしてほしい操作／主ボタン**: 「記録を保存」。
- **副操作**: 写真を追加、見せる相手を選ぶ、詳細を追加、下書きを削除。
- **情報の表示順**: 愛車名・お題ヒント → タイトル／本文 → 時期 → 写真・説明 → 見せる相手 → 保存。整備の詳細は任意の段階的開示にする。
- **表示してはいけないもの**: 写真単独の公開切り替え、内部保存経路、不要な必須項目、AIを使わないと保存できない導線。
- **初回／空状態**: タイトルなしでも不自然な強制入力をせず、保存に必要な最小情報を示す。
- **読み込み／エラー**: 保存中の進捗をボタンで示す。失敗時は安全な原因カテゴリを示し、入力・下書き・既存写真を保持する。
- **保存成功状態**: サーバー保存成功後だけ完了画面へ。写真未送信や共有処理失敗を完全成功と扱わない。
- **スマートフォン／アクセシビリティ**: 写真プレビュー、説明、順序変更、削除を大きなタップ対象で提供。エラー項目へfocusを移す。
- **戻る操作**: 離脱前に下書きを保持する。保存途中は二重送信しない。
- **関連する計測イベント**: `record_save_started`、`record_saved`、`record_save_failed`、`photo_added`、`audience_changed`、`draft_saved`。
- **CURRENTで再利用できるもの**: `journal-form`、`quick-event-form`、写真処理、公開範囲統一、下書き、保存エラー表示。
- **NEEDS_DECISION**: 公開範囲を本文の前に見せるか保存直前に見せるか。推奨は保存直前の「見せる相手」で一度だけ確認する。

## 7. 投稿／記録詳細

- **画面の目的**: 一つの愛車の出来事を読み、愛車・所有者・関連する次の行動へ進む。
- **対象ユーザー／来る理由**: フィードで見つけた記録を読む、自分の過去を見返す。
- **最もしてほしい操作／主ボタン**: 記録を読む。操作が必要な場合は、所有者なら編集、他者ならいいねまたはGarage閲覧。
- **副操作**: 投稿者のGarage、愛車ページ、いいね、再読み込み、編集。
- **情報の表示順**: 愛車と所有者 → タイトル・時期 → 本文 → 写真 → 反応・関連導線。
- **表示してはいけないもの**: 内部ID、写真の別公開設定、不要な管理情報。
- **初回／空状態**: 直接URLで権限がない時は存在を漏らさず安全に戻り先を示す。
- **読み込み／エラー**: 本文と写真の取得失敗を分ける。写真は再読み込み可能にし、P-069のような失敗を記録全体の削除に結びつけない。
- **保存成功状態**: 編集後は更新内容を表示し、再送信しない。
- **スマートフォン／アクセシビリティ**: 投稿者、車両、本文、いいねを別のタップ対象にし、ネストしたリンクを作らない。
- **戻る操作**: 直前のホーム・Garage・検索へ戻る。
- **関連する計測イベント**: `record_opened`、`like_changed`、`owner_garage_opened`、`vehicle_page_opened`、`shared_photo_retry`。
- **CURRENTで再利用できるもの**: `/journal/[id]`、記録カード、写真表示、いいね、公開Garage導線。
- **NEEDS_DECISION**: 記録にコメント機能を入れるか。推奨はαでは追加せず、いいねとフォローで反応を検証する。

## 8. 投稿／記録完了

- **画面の目的**: 記録が愛車の歴史に加わった実感を返し、次の自然な行動を選ばせる。
- **対象ユーザー／来る理由**: 保存を終えたオーナー。
- **最もしてほしい操作／主ボタン**: 「ガレージで見る」。
- **副操作**: 記録を見る、もう一つ記録を残す、ホームへ戻る。
- **情報の表示順**: 保存成功 → 愛車名・愛称 → 記録タイトル → 主ボタン → 副操作。
- **表示してはいけないもの**: 再送信ボタン、技術的な保存ID、課金アップセル、無関係なフィード。
- **初回／空状態**: 最初の記録なら「この愛車の歴史が始まりました」と表現してよいが、過度なゲーム演出は避ける。
- **読み込み／エラー**: 完了画面は保存成功後だけ表示する。保存失敗時は入力画面と下書きを維持する。
- **保存成功状態**: 作成された記録と対象車両を明示する。再読込・戻るで再送信しない。
- **スマートフォン／アクセシビリティ**: 成功を色だけで示さず、見出し・本文で伝える。主要行動を一番押しやすい位置に置く。
- **戻る操作**: Garage、記録詳細、ホーム。ブラウザ戻るは入力の再送信ではなく、保存済み記録または安全な入力開始へ。
- **関連する計測イベント**: `record_completion_viewed`、`completion_garage_selected`、`completion_record_selected`、`completion_next_record_selected`、`completion_home_selected`。
- **CURRENTで再利用できるもの**: `journal-completion`、保存成功後の遷移、同一車両での再作成導線。
- **NEEDS_DECISION**: 完了画面から共有を出すか。推奨は、新しい外部共有を作らず、現在の共有範囲を人間QAで確認するまで出さない。
