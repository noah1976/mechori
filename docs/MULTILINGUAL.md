# MULTILINGUAL

## 目的

初期UIは日本語・英語だけを提供しますが、MECHORIのデータ、検索、翻訳、画面構造は言語が増える前提にします。EU圏を含む展開時に、原文の移行、DBの全面変更、画面ごとの二択処理の書き直しを避けます。

追加言語の優先順位は事前に固定せず、車種コミュニティ、協力者、検索需要、翻訳確認者を確保できる地域から決めます。

## 分離する概念

次を一つの`locale`へ混在させません。

| 概念 | 例 | 用途 |
| --- | --- | --- |
| UIロケール | `ja`, `en` | ナビゲーション、入力、エラー、安全表示 |
| 原文言語 | `it`, `de-DE`, `fr` | Journal、整備記録、出典の原文 |
| 翻訳先言語 | `en`, `ja`, `it` | 派生翻訳の識別 |
| 地域 | `JP`, `DE`, `IT` | 法務、公開条件、必要な場合だけ保持 |
| タイムゾーン | `Asia/Tokyo` | 日時表示。原文言語から推測しない |
| 単位系 | `km`, `mi` | 車両・記録ごとに保持。UI言語から変換しない |
| 通貨 | `JPY`, `EUR`, `GBP` | ISO通貨コード。言語から推測しない |

言語はBCP 47タグとして保持し、`pt_BR`等の入力は`pt-BR`へ正規化します。UIが未対応の言語で書かれた投稿も、原文言語を保持したまま登録可能にします。

## UI辞書

- 対応UI言語は`packages/core/src/language.ts`の一覧を正本にする。
- 各辞書は同じ翻訳キーを必須とし、言語追加時の欠落を型チェックで検出する。
- 言語選択は二択トグルにせず、追加可能な選択肢リストとして表示する。
- 画面の新規文言は三項演算子へ直接追加せず、段階的に`@mechori/i18n`のキーへ移す。
- 翻訳キーに完成した英語文を使わず、意味が安定した識別子を使う。
- 数、日付、相対時刻、複数形は文字列連結せず、対象ロケールのFormatterとメッセージ引数で組み立てる。
- 未翻訳キーは英語へフォールバックできる境界を設けるが、安全・同意・法務文言ではフォールバック表示のまま公開しない。

現行プロトタイプには日英を直接分岐する文言が残っています。新規画面では増やさず、外部公開前に主要導線から辞書へ移します。

## 投稿原文と翻訳

- `bodyOriginal`、`originalText`、`sourceLanguage`を正本とし、翻訳で上書きしない。
- 翻訳は`ContentTranslation`として、対象エンティティ、対象フィールド、原文版、原文言語、翻訳先、方法、Provider・モデル版、確認状態を保持する。
- 原文が更新された翻訳は`outdated`にし、古い翻訳を現行原文として表示しない。
- 機械翻訳、人間翻訳、人間確認済みを区別する。
- 自動翻訳がない場合も原文を表示でき、未翻訳であることを示す。
- 非公開投稿やフォロワー限定投稿を、本人同意なしに外部翻訳Providerへ送らない。
- 全投稿を全言語へ事前翻訳せず、閲覧需要のある組合せを必要時に翻訳し、同じ原文版の結果を再利用する。

### α実装

- Workspaceスキーマv11で、Journalのタイトルと順序付き本文ブロックの翻訳を`ContentTranslation`として保存する。
- 表示言語と原文言語が異なる場合、現行原文版に対する完全な翻訳があれば、写真・動画の位置を保ったまま翻訳文へ差し替える。
- 翻訳が欠けている、拒否済み、または原文更新後に古くなった場合は原文を表示し、未翻訳であることを明示する。
- 投稿者本人は記事詳細の「翻訳」から日英の別言語版を追加できる。手入力した翻訳は`human`かつ`human_reviewed`として保存する。
- 新規JournalではUI表示言語と原文言語を分離して選択でき、日本語文字を含む投稿は外部送信なしの簡易判定で日本語原文として保持する。
- 現段階では投稿本文を外部翻訳Providerへ送らない。将来の機械翻訳は、送信対象、公開範囲、同意、費用上限を承認した後、同じ`ContentTranslation`境界へ接続する。

## 検索と集合知

- 症状、部位、作業、結果、危険領域は言語非依存コードを持ち、各言語のラベル・同義語を別管理する。
- 検索語を英語へ変換するだけで済ませず、原語、別名、車種固有語、表記揺れを検索語彙へ関連付ける。
- メーカー表示は既知の言語別名から世界共通のアルファベット表記へ統一し、入力原文も保持する。
- 車名の翻字と市場別名称を区別する。表示言語による`スカイライン` / `SKYLINE`の切替と、`ヴィッツ` / `YARIS`の市場差を同じ翻訳処理で上書きしない。
- 集合知は表示文字列ではなく、確認できた`modelFamilyId`、`generationId`、`variantId`と確認状態で関連付ける。
- 原文と翻訳を同一の独立事例として二重計上しない。
- AIが翻訳した原因候補や作業を、原文にない新しい整備事実として追加しない。
- 出典リンクは可能な限り原文へ向け、利用者が翻訳から原文へ戻れるようにする。

## EU展開で追加確認する項目

- 対象国ごとの利用規約、プライバシー通知、Cookie・分析同意
- データ処理地域、外部AI・翻訳Provider、削除・開示対応
- 右ハンドル・左ハンドル、km・mi、EUR・GBP等を言語と分離できているか
- 車検・整備記録簿・資格・安全表示の国別差を、一国の用語へ寄せていないか
- 翻訳品質を確認できるオーナー、メカニック、運営協力者がいるか
- 安全文言と公開ナレッジの翻訳訂正・緊急非公開化を運用できるか

## 導入ゲート

新しいUI言語を公開する前に、主要導線、入力検証、エラー、安全警告、公開範囲、通報、データ権利、認証復旧をその言語で確認します。ナビゲーションだけ翻訳された状態を「対応済み」と表示しません。
