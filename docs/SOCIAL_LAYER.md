# SOCIAL_LAYER

## 文書の目的

MECHORYに、整備記録を続ける楽しさと「見せたい・見てもらいたい」体験を加えます。ただし、SNSの人気と整備情報の信頼性を混同せず、知識基盤へつながる入口として設計します。

## 三つの情報層

### 1. 整備記録

車両履歴の正本です。日付、走行距離、整備箇所、作業、部品、費用、結果等を構造化し、初期値は非公開とします。

### 2. Garage Journal

オーナーが自分の言葉で自由に書く車両ブログです。

- タイトルの下に、段落、見出し、引用、写真、画像、動画を順序付きブロックとして自由に構成できる。
- メディアは本文末尾への一括添付ではなく、語りたい箇所へ挿入できる。故障、路上停止、失敗、復旧までを本人らしい読み物として残せる。
- 整備記録を任意で紐付けると、日付、走行距離、整備箇所、実施作業等の定型情報を別枠で表示できる。
- 工場整備、DIY、故障時の気持ち、部品探し、納車後の経過等を、成果自慢に限定せず書ける。
- AIはブログ本文を代筆・自動生成しない。文章の主役と著作者はオーナー本人とする。
- 公開範囲は非公開、フォロワー、公開から選べるようにする。初期値は非公開とする。
- Journalを書かず、構造化整備記録だけを保存・共有候補化する経路も同等に成立させる。

### 3. 公開ナレッジ

検索回答の根拠となる構造化情報です。整備記録やGarage Journalそのものとは分離し、出典、車両一致範囲、確認状態、安全性、反対結果を保持します。

## AIの役割

AIはGarage Journalを「うまいブログ」に書き換えるためには使いません。次の補助に限定します。

1. 公開または本人が処理を許可した本文から、症状、原因候補、確認箇所、作業、部品、結果の候補を抽出する。
2. 抽出候補を本文の該当箇所とともに本人へ示す。
3. 本人が確認した項目だけを、整備記録への追記または共有ナレッジ候補として扱う。
4. 検索時は複数の公開JournalとKnowledgeCaseから根拠に拘束された要約を先に示し、各主張から元投稿・事例へ遡れるようにする。

自由文に書かれた内容は、AI抽出だけで確認済み事実へ昇格させません。公開Journalだけを根拠に、原因や修理方法を断定する回答も作りません。元投稿にない作業や部品をAIが補完してはなりません。

## 検索時の情報区分

検索結果では最低でも次を分離します。

- `確認済みナレッジ`: 公開・確認工程を経たKnowledgeCase。
- `関連するオーナー記録`: 条件に近い公開Garage Journal。経験談であり未確認情報を含み得る。
- `情報不足`: 根拠が足りず、文章化できない状態。

関連Journalの閲覧数、リアクション数、フォロワー数を、原因候補の確からしさ、検索順位、安全評価へ使用しません。

## フォロー対象

人だけでなく、次の対象をフォロー可能にする案を検証します。

- オーナーまたはメカニックのプロフィール
- 個別車両
- 車種

これにより、人物の人気だけでなく「このBarchettaのその後を見たい」「この車種の記録を追いたい」という動機を扱えます。

## フィード

初期フィードは時系列を基本とします。

- フォロー中のGarage Journal
- フォロー車両の新しい整備記録のうち、所有者が共有を許可した概要
- フォロー車種の公開ナレッジ追加・重要訂正
- フォロー中のProfessionalプロフィールによる公開情報

不透明な推薦順位、投稿数ランキング、過度なフォロワー競争は初期実装へ含めません。

## 独立した公開設定

以下は一括公開せず、別々に制御します。

- 整備記録の公開・共有候補提出
- Garage Journalの公開範囲
- Journalからのナレッジ候補抽出への同意
- 車両プロフィールの公開範囲
- 写真の公開

Journalを削除しても、すでに確認・匿名化されたKnowledgeCaseをどう扱うかは別状態として管理します。逆に、Journalを公開しただけで整備記録やKnowledgeCaseを公開しません。

## 写真・画像・動画とプライバシー

Garage Journalの写真、画像、動画にも`docs/MEDIA_PRIVACY.md`の公開ゲートを適用します。

- 原本をそのまま公開しない。
- EXIF・位置情報を除去する。
- ナンバープレート、顔、住所等の候補をマスクする。
- 自動検出後もユーザーの目視確認を必須にする。
- 未確認画像がある投稿は公開できない。
- 動画は全フレームと音声を確認し、位置・撮影端末等のメタデータを除去する。
- メディア本体とJournal本文・公開状態を分離し、非公開メディアへの公開URLを作らない。

## モデレーション

- 他者への誹謗中傷、無断転載、個人情報、危険な断定、スパムを通報できる。
- Journal本文の人気と、投稿者の整備能力・Professional確認を結び付けない。
- いいねやフォロー獲得のための虚偽を検出・通報・訂正できる。
- 元の自由文、AI抽出候補、本人確認結果、公開KnowledgeCaseを追跡可能にする。

## 初期プロトタイプの範囲

外部接続なしの次回ローカル検証では、次を対象にします。

- Garage Journalの順序付きブロック編集、任意位置への画像・動画挿入、非公開保存
- DEMOの公開範囲切り替え
- 整備記録との任意リンクと定型情報表示
- プロフィール、車両、車種のDEMOフォロー
- 時系列のフォローフィード
- Journalからのナレッジ候補は「抽出候補を見る」までとし、自動確定しない
- 画像・動画をブラウザ内へ保存し、再読み込み後も非公開Journalで閲覧できる
- メディアの説明文を必須とし、画像以外の利用者にも内容を伝える

初期対象外:

- AIによるブログ本文生成
- 実AI抽出
- コメント、DM、グループ、リポスト
- 推薦アルゴリズム
- フォロワーランキング
- 実画像・動画の公開、自動マスキング、メタデータ除去
