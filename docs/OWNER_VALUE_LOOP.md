# OWNER_VALUE_LOOP

## 目的

整備記録を入力する本人へ、集合知への貢献より先に明確な価値を返します。工場へ依頼した整備も、自分で作業した整備も同じ車両履歴として扱い、DIY実績や人気投稿だけに依存しない継続理由を作ります。

## 初期価値ループ

1. 整備日、走行距離、入庫内容を記録する。
2. 車両ごとの時系列、作業数、部品情報、未解決事項が自動整理される。
3. 履歴の整理状況と次に追記すべき内容が見える。
4. 工場へ見せる資料、自分のデータ出力、売却時の履歴書へ再利用できる。
5. 希望する記録だけを匿名化確認へ進め、集合知へつなげる。

共有しなくても1から4の価値を利用できます。投稿を強制したり、データ出力を有料・共有条件にしたりしません。

## History Level

History Levelは車両ごとの履歴整理状況です。整備能力、車両状態、投稿の正確性、資産価値を表しません。

プロトタイプでは変更しやすい暫定条件を使います。

| Level | 表示 | 暫定条件 |
| --- | --- | --- |
| 0 | 未登録 | 整備イベント0件 |
| 1 | 記録を開始 | 1件以上 |
| 2 | 履歴を整理中 | 3件以上かつ作業3件以上 |
| 3 | 継続して記録 | 6件以上、記録期間180日以上 |

単純な投稿件数競争にしないため、Levelは非公開記録だけでも上がります。検索順位、課金特典、Professional確認、KnowledgeCaseの信頼表示には利用しません。

## 履歴の節目

プロトタイプでは事実から機械的に確認できる次の節目だけを表示します。

- 最初の記録
- 1回の入庫に複数作業を整理
- 作業後の結果を記録
- 共有候補を匿名化・運営確認へ提出
- 確認を経たKnowledgeCaseの公開

未解決、再発、分からないという正直な記録を不利にしません。節目の取消・再評価が必要な場合も、個人への制裁表示ではなく根拠状態の更新として扱います。

## 外部共有の初期方針

SNS SDKは追加せず、共有文のプレビューとコピーから始めます。初期共有文には次を含めません。

- 走行距離
- 費用
- 正確な整備日
- 非公開メモ
- 故障症状や危険情報
- 車両個体を特定し得る情報
- 整備能力や車両状態を保証する表現

将来、車両写真を含むカードを作る場合は、`docs/MEDIA_PRIVACY.md`の公開ゲートを通過した派生画像だけを使用します。

## データ出力

本人の整備履歴は、共有や課金と無関係に機械可読形式で出力できるようにします。ローカルプロトタイプではバージョン付きJSONを端末へ保存し、外部サービスへ送信しません。

本番では次を追加検討します。

- 人が読める整備履歴PDF
- 工場へ期限付きで見せる共有画面
- 車両譲渡用の履歴書
- サービス終了時の一括出力

## 計測する仮説

- 履歴サマリーを見た人が2件目を登録する割合
- 未解決件から結果追記へ進む割合
- JSON・PDF・工場共有の利用率
- 共有文のプレビュー後に共有を中止した割合
- History Levelが入力品質や虚偽投稿へ与える影響

Level条件、名称、バッジの見せ方は利用テスト後に調整します。

ローカルプロトタイプでは、工場へ画面提示または印刷できる車両履歴を追加しました。これはサーバーへ共有URLを発行せず、現在の端末内データから都度生成します。
