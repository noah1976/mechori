# SCREENS

## 文書の目的

初期MVPの主要画面について、利用者、目的、主要操作、状態、安全・プライバシー上の責務を定義します。画面の見た目を確定する文書ではなく、各画面が何を達成するかを定める文書です。

Webと将来のExpoアプリで、データ、状態、権限、入力検証は共有します。ナビゲーションやカメラ等の端末固有UIはクライアントごとに最適化します。

## 体験の優先順位

初期MVPの中心体験は次の順です。

1. 困っている症状や部品から、近い車両の公開事例を探す。
2. 紙や既存資料から、自分の整備履歴を少ない修正で作る。
3. 自分の整備履歴を確認・訂正する。
4. 確認済み記録の一部を共有ナレッジ候補として提出する。
5. Garage Journalへ自分の言葉で経験を書き、車両・車種を通じて他の利用者とつながる。

ホームはマーケティング用ランディングページや一般的なダッシュボードにしません。読んでみたい所有体験、Journal投稿、整備記録だけの入力、症状検索を同じ循環の入口として提示します。

## 主要フロー

### F-01 症状から事例を探す

`ホーム / 検索起点` → `検索結果` → `ナレッジ詳細`

- 完全一致と検索範囲を広げた結果を混同しない。
- 結果がない場合も、AIが架空の回答を作らない。
- 詳細では出典、確認状態、一致範囲、安全警告を本文より先に判断できる。

### F-02 紙から履歴を作る

`記録追加方法` → `取込元選択` → `処理状態` → `抽出結果確認` → `整備イベント確認` → `非公開保存`

- OCR・AI結果は下書きであり、保存前にユーザーが確認する。
- 1つの資料から複数の整備イベント、1つのイベントから複数作業を作成できる。
- 読めない項目を推測で確定しない。
- 保存の初期値は非公開とする。

### F-03 手入力で履歴を作る

`記録追加方法` → `整備イベント編集` → `非公開保存` → `整備イベント詳細`

- 最初に入庫・整備機会の情報を入力し、その配下へ作業を追加する。
- 不明な項目は空欄または未確認状態で保存できる。

### F-04 記録を共有候補にする

`個人記録詳細` → `共有項目確認` → `匿名化確認` → `運営確認待ち`

- 個人記録そのものを公開状態へ変更しない。
- 共有対象から個人情報、原本、非公開メモを除く。
- 運営確認前に公開検索へ出さない。

### F-05 Garage Journalを書く

`車両プロフィール / フィード` → `Journal編集` → `非公開保存` → `公開範囲確認` → `Journal詳細`

- 本文は本人が自由に書き、AIによる自動生成を初期導線にしない。
- 段落、見出し、引用、写真、動画を好きな順序で挿入できるブロック編集とする。
- Journalを書かず整備記録だけを残す導線を常に用意する。
- 整備記録を任意で関連付け、定型情報と自由文を別の領域に表示する。
- Journal公開と、整備記録・ナレッジ候補の公開を別操作にする。
- Journal本文から抽出した候補は、本人確認前にナレッジへ反映しない。

## 初期MVP画面

### S-001 ホーム / 検索起点

- 主利用者: オーナー、メカニック
- 目的: 登録車両を検索範囲として、症状・部品・キーワード検索をすぐ始める。
- 主要表示: 対象車両、検索欄、記録取込、手入力、未確認下書き件数、最近の個人記録。
- 主要操作: 検索、記録取込、手入力、車両切替。
- 空状態: 車両未登録の場合は、車両登録と車両を指定しない検索を提示する。
- ログイン時の月次表示: 今月の整備記録、Journal、未解決・要追記、フォロー更新を一つの帯にまとめ、毎日投稿を求めず月内に戻る目的を提示する。
- 禁止: 大きなブランド説明、人気競争型フィード、根拠のない故障傾向、広告を第一画面の主役にしない。

### S-002 My Garage / 車両一覧

- 主利用者: オーナー
- 目的: 自分が管理する車両と、その記録状態を確認する。
- 主要表示: 一般的な車両仕様、記録件数、未確認下書き、未解決記録、最終更新日。
- 主要操作: 車両選択、車両追加・編集、履歴表示、検索範囲へ設定。
- プライバシー: VIN全文、ナンバープレート、正確な保管場所を要求・表示しない。

### S-003 車両登録・編集

- 主利用者: オーナー
- 目的: 整備記録と検索範囲に必要な一般仕様だけを登録する。
- 主要項目: メーカー、車種、年式、エンジン、トランスミッション、ステアリング位置、仕向け地、仕様メモ。
- 登録保証: 車種候補に存在しなくても、メーカー・車種の自由入力で即時登録を完了できる。年式・型式・仕様は不明のまま開始し、後から補完できる。
- 禁止: `その他`だけを愛車名として表示する、車種追加申請の承認まで利用を止める、未確認車種という理由で記録・検索・Journalを制限する。
- 状態: 確認済み、不明、ユーザー入力。
- 未確定: FIAT Barchetta固有の仕様分類粒度。
- 補助導線: メーター履歴は通常画面の主役にせず、整備イベントで交換・修理等を記録した場合だけ内部履歴へ追加する。現在値の逆行だけで入力エラーにしない。

### S-004 整備履歴

- 主利用者: オーナー
- 目的: 車両ごとの整備イベントを時系列で確認する。
- 主要表示: 整備日、走行距離、イベント概要、作業件数、解決状態、確認状態、公開関連状態。
- 主要操作: 絞り込み、詳細表示、訂正、記録追加。
- 注意: 1件のカードを1部品交換とみなさず、1回の入庫・整備機会として表示する。

### S-005 整備イベント詳細

- 主利用者: オーナー
- 目的: 1回の入庫・整備機会と、その配下の複数作業を確認・訂正する。
- 主要表示: 日付、その時点の走行距離、出典、症状・観察事項、作業一覧、使用部品、費用、結果、確認状態、訂正履歴。メーター交換・修理を行った記録だけ、その事実を補足表示する。
- 主要操作: 編集、作業追加、共有候補作成。
- 安全: 原因候補と確認済み事実を分離し、危険作業は強い警告を表示する。

### S-006 記録追加方法

- 主利用者: オーナー
- 目的: 最も負担の少ない入力方法を選ぶ。
- 選択肢: 紙・PDF・画像、手入力、将来の音声、CSV。
- 初期MVP: 手入力を利用可能にし、紙・PDF・画像はローカル検証機能から段階導入する。
- 表示: 外部送信の有無、原本保存の有無、処理後の削除方針。

### S-007 取込処理状態

- 主利用者: オーナー
- 目的: 複数ページの処理進捗、失敗、再試行、原本削除状態を確認する。
- 主要状態: 待機、OCR中、構造化中、確認待ち、一部失敗、失敗、完了、原本削除済み。
- 注意: 進捗率を根拠なく表示せず、ページまたは工程単位の状態を使う。

### S-008 抽出結果確認

- 主利用者: オーナー
- 目的: OCR・AI下書きの怪しい箇所だけを直し、複数記録をまとめて確定する。
- 主要表示: 抽出元の該当箇所、候補値、確度、推測・判別不能・要確認、ページ番号。
- 主要操作: 修正、未確認のまま保持、候補削除、イベント分割・結合、作業分割・結合。
- 必須確認候補: 日付、走行距離、部品番号、費用、危険領域、公開対象。
- 走行距離: 過去値より小さい場合も拒否しない。メーター交換・修理が明細に記載されている場合だけ、その事実と交換後の表示値を確認できる。
- 禁止: AI候補を一括で確認済み事実にする操作を初期値にしない。

### S-009 手入力 / 整備イベント編集

- 主利用者: オーナー
- 目的: 1回の整備イベントと複数作業を入力する。
- 構成: イベント共通情報、走行距離、症状・観察事項、作業行、部品行、費用、結果、非公開メモ。メーター交換・修理は任意チェックを選んだ場合だけ追加項目を表示する。
- 初期状態: 非公開、ユーザー入力、未共有。
- 注意: 原因候補を必須にしない。症状がない定期整備も保存できる。
- 入力継続: 入力途中を端末内下書きへ保存し、再読み込み後に復元・破棄できる。空のフォームは下書きとして残さない。
- 保存失敗: 本保存が端末へ完了するまで画面上の正本へ反映せず、失敗理由と下書き保持を表示する。

### S-010 ナレッジ検索結果

- 主利用者: オーナー、メカニック
- 目的: 自分の車両とどこまで一致する事例かを比較する。
- 主要表示: 複数投稿・事例から根拠に拘束して文章化した要約、確認箇所、原因候補、対応、部品、結果、危険度、出典リンク。
- 表示順: 要約を主表示し、その下に主張の根拠となる投稿・事例を表示する。投稿一覧を回答の代わりにしない。
- 範囲: 同仕様、同車種別年式、共通エンジン等を段階表示する。具体的な拡張順はデータ確認後に決める。
- 空状態: 検索条件を広げる選択肢と、情報募集の将来導線を示す。

### S-011 ナレッジ詳細

- 主利用者: オーナー、メカニック
- 目的: 公開事例を参考情報として安全に評価する。
- 主要表示: 対象仕様、一致範囲、確認された事実、原因候補、確認箇所、実施作業、部品、結果、出典、訂正履歴。
- 安全: `CRITICAL`では専門家確認を強く案内し、修理指示の表現を使わない。
- 操作: 参考になった結果の記録、訂正・危険情報の通報。初期ベータは一部を手動運用できる。

### S-012 共有候補確認

- 主利用者: オーナー
- 目的: 個人記録から共有する項目だけを確認する。
- 主要表示: 共有される情報、除外される情報、匿名化状態、出典、危険度、運営確認が必要なこと。
- 操作: 提出、戻って修正、共有を取り止める。

### S-013 車両履歴サマリー

- 主利用者: オーナー
- 目的: 記録入力によって本人へ返る価値を、その場で確認する。
- 主要表示: History Level、整備イベント数、作業数、部品情報数、未解決件数、履歴の節目。
- 主要操作: 自分のデータをJSONで出力、個人情報を含まない共有文をプレビュー・コピー。
- 注意: History Levelと節目は、整備能力、車両状態、投稿の正確性、検索順位、Professional認証を表さない。
- プライバシー: 共有文の初期値に走行距離、費用、正確な日付、症状、非公開メモを含めない。

### S-014 工場向け車両履歴

- 主利用者: オーナー、整備工場
- 目的: 専門外の工場でも、車両仕様、過去整備、未解決事項を短時間で把握できるようにする。
- 主要表示: 一般仕様、現在のメーター表示、未解決記録、整備イベントと作業結果。
- 主要操作: 画面提示、ブラウザ印刷、端末のPDF保存。
- 安全: オーナー記録であり、実車診断、整備指示、整備書、Professional確認の代替ではないことを常時表示する。
- プライバシー: VIN全文、ナンバープレート、住所、連絡先、正確な保管場所を含めない。

### S-015 Garage Journal編集・詳細

- 主利用者: オーナー
- 目的: 整備や所有体験を本人の言葉で自由に残す。
- 主要入力: タイトル、段落・見出し・引用・写真・画像・動画の順序付きブロック、各メディアの説明、任意の関連整備記録、公開範囲。
- 編集体験: メディアは末尾添付に限定せず任意のブロック間へ挿入でき、上下移動・削除ができる。故障や路上停止も読み物として楽しく残せる。
- 定型表示: 関連記録から投稿者が選んだ日付、走行距離、整備箇所、作業。
- AI: 本文を生成しない。本人が許可した場合のみ、整備記録・ナレッジ候補となる項目を抽出して別画面で確認する。
- プライバシー: 初期値は非公開。画像・動画公開ゲートと項目単位の表示確認を必要とする。自動除去が未実装のプロトタイプでは実ファイル付き投稿を非公開に限定する。
- 入力継続: 文章と公開設定を端末内下書きへ保存し、再読み込み後に復元・破棄できる。写真・動画のファイルは下書きへ複製せず、再選択件数を明示する。

### S-016 フォローフィード

- 主利用者: オーナー、メカニック
- 目的: フォローしたプロフィール、車両、車種の更新を時系列で見る。
- 主要表示: Garage Journal、共有を許可された整備概要、公開ナレッジの追加・訂正。
- 主要操作: プロフィール・個別車両・車種のフォロー、プロフィールのミュート・ブロック、表示管理からの解除。
- 禁止: いいね・フォロワー数による信頼度表示、不透明な推薦順位、非公開記録の露出。

### S-017 Journal抽出候補確認

- 主利用者: Journal投稿者
- 目的: 自由文から見つかった症状、作業、部品、結果等の候補を確認する。
- 主要操作: 整備記録へ追記、共有候補へ追加、却下、後で確認。
- 禁止: 一括自動確定、原文の自動書換え、未確認候補の公開ナレッジ利用。

### S-018 ログイン・招待登録

- 主利用者: 招待されたオーナー、既存利用者
- 目的: 公開Journalを読む状態から、自分のGarageと非公開記録へ短い手順で移る。
- 主要操作: Googleログイン、SNSで共有された招待URLまたは招待コード付き新規登録、ログアウト、元の保護画面への復帰。
- 未ログイン表示: ホーム、ナレッジ検索、公開Journalだけを表示する。個人の整備履歴、非公開・フォロワー限定Journal、フィード、Garage、記録入力は表示しない。
- プロトタイプ制約: Google認証を想定した端末内モックで、外部Providerへ接続しない。本番のOAuth、アカウント復旧、Provider追加は未実装。

### S-018A アプリ内通知

- 主利用者: ログイン利用者
- 目的: メールへ依存せず、フォロー対象の更新、運営からの重要連絡、招待結果等をMECHORI内で確認する。
- 初期表示: 未読件数、通知種別、発生日時、対象へのリンク、既読状態。
- 制約: 非公開本文を通知文へ複製しない。通知数や既読速度を人気・信頼度・検索順位へ利用しない。メールとWeb Pushは別の明示設定とする。

### S-019 プロフィール公開設定・公開プロフィール

- 主利用者: オーナー、公開プロフィール閲覧者
- 目的: Journal等と独立してプロフィールページの閲覧者と表示項目を制御する。
- 公開範囲: 自分だけ、プロフィールの直接フォロワー、公開。
- 表示項目: 役割、自己紹介、愛車のメーカー・車種・年式、所有期間、公開Journal件数。表示名は投稿者識別のため常時表示する。
- 禁止: VIN、ナンバープレート、正確な保管場所、所有期間や投稿数による信頼度評価。

### S-020 Journal通報

- 主利用者: ログイン利用者
- 目的: 他者のJournalに含まれる個人情報、危険な断定、嫌がらせ、権利侵害、スパム等を運営確認へ送る。
- 主要操作: 理由選択、500文字以内の任意補足、送信、受付確認。
- 制約: 自分の投稿と、同じ利用者による対応中の重複通報を受け付けない。緊急通報の代替と表現しない。

### S-021 通報・モデレーション運営DEMO

- 主利用者: 将来の運営者。現行はローカル操作確認のみ。
- 目的: 受付、確認開始、修正依頼、一時非公開、問題なし終了、復元の最小運用を確認する。
- 主要表示: 対象Journal、理由、補足、状態、通報者、受付日時、操作履歴。
- 安全: 一時非公開を削除と区別し、直接URLとナレッジ候補にも適用する。本番の管理者権限や監査を提供する画面ではない。

## 運営画面

初期ベータでは、公開候補一覧、候補詳細、公開・訂正依頼・見送り、緊急非公開化を最小範囲で用意します。法的要請、完全な通報管理、監査検索は公開前要件ですが、初期内部検証では手動台帳で代替できます。

## WebとExpoの境界

| 共通化するもの | Web固有 | Expo固有 |
| --- | --- | --- |
| データ型、状態遷移、入力検証、権限、安全ルール、翻訳キー | URL、ブラウザファイル選択、デスクトップ管理画面 | カメラ連続撮影、端末内OCR、オフライン下書き、プッシュ通知 |

## プロトタイプへの反映方針

現行プロトタイプは画面遷移と状態表現の確認用として保持します。ホームは、読まれるJournal、Journal投稿、整備記録だけの入力、ナレッジ検索、最近の履歴を同じ体験にまとめています。Garage Journal編集・詳細、フォローフィード、未ログイン表示、ローカル認証モックはローカルDEMOへ反映済みです。

Journal本文は本人の自由記述をそのまま保持します。整備日、走行距離、整備箇所・作業は、任意に関連付けた整備記録から項目単位で表示します。AI本文生成、実AI抽出、コメント、DM、ランキング、推薦アルゴリズムは実装していません。

プロフィール、個別車両、車種のフォロー候補は識別可能な表示にし、自分の車両はフォロー候補から除外します。人気指標はナレッジ信頼度や検索順位へ接続しません。実物資料による取込確認ができるまで、OCR精度や自動入力の完成度を画面上で保証しません。

実物資料がない段階でも、`/import/review-demo`で`FieldAssertion`の候補値、確度、推測・判別不能、確認・除外、非公開下書き作成前ゲートを操作確認します。この画面は実OCR・AI・原本表示・保存を行いません。
