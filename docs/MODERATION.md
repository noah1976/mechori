# MODERATION

## 基本方針

MECHORI は UGC を扱うため、投稿の安全性、権利侵害、誤情報、危険情報に対応できる設計にします。許諾のないフォーラム、ブログ、整備書等を初期データとして無断転載しません。

## 将来対応する機能

- 投稿の通報
- 一時非公開
- 投稿者への修正依頼
- ユーザーのブロック
- ユーザーのミュート
- 管理者削除
- 削除理由
- 異議申立て
- モデレーション履歴
- 著作権侵害の削除申立て
- 情報源・許諾・ライセンスの管理
- 編集・訂正履歴

## 初期実装

- 投稿に公開／非公開／一時非公開などの状態を持たせる。
- 管理者が危険情報や誤情報の疑いがある投稿を非公開化できる設計にする。
- 出典、許諾、ライセンスの記録欄を将来追加できるようにする。
- 利用者がプロフィールをミュートし、フォローを維持したまま自分のフィードから投稿を隠せる。
- 利用者がプロフィールをブロックし、対象プロフィール・個別車両へのフォロー解除、投稿・候補・直接閲覧の抑止、解除管理を行える。
- Journalを、個人情報、危険な断定、嫌がらせ、権利侵害、スパム、その他の理由で通報できる。
- 同じ利用者による同じJournalへの対応中通報は重複登録しない。
- 通報受付、確認中、修正依頼中、一時非公開、問題なし終了を区別し、操作主体、操作種別、日時だけの最小履歴を保持する。
- 一時非公開のJournalはフィード、直接URL、ナレッジ候補から除外し、削除とは分ける。

## ローカルプロトタイプ

- `/journal/[id]/report`で通報し、`/moderation`で最小状態遷移を操作できる。
- 通報と操作履歴はlocalStorage試作データへ保存し、外部送信、通知、実際の管理者権限判定を行わない。
- 通報件数や状態を、人気、投稿者の信頼度、Professional確認、検索順位へ使用しない。
- 修正依頼は状態だけを検証し、投稿者通知や編集ロックはまだ行わない。
