# ARCHITECTURE

## 想定構成

- Web: Next.js
- 共通バックエンド: Supabase
- Web公開: Vercel
- 将来ネイティブアプリ: Expo / React Native
- AI: OpenAI API等を将来利用
- OCR: 初期はMac等のローカル処理、将来は端末内OCRを優先

この文書は方針のみを示します。現時点ではアプリケーションコード、データベース、外部サービス接続、依存パッケージ導入を行いません。

## 設計原則

- 業務ロジックをNext.js固有の実装へ密結合しない。
- データ型、入力検証、多言語コード、API処理をWebと将来アプリで共有しやすくする。
- 外部サービスは差し替え可能な境界を持たせる。
- 個人情報、AI処理、モデレーション、監査ログを後から追加できる余地を残す。
- 税率、法的期限、料金、外部サービス仕様をコードへ固定しない。

## 初期実装

- `apps/web`、`packages/core`、`packages/shared` 等の構成は候補だが、実装開始前に所有者へ確認する。
- 車両、整備イベント、作業、部品、症状、結果、公開状態、確認状態を中心概念にする。
- 認証情報とアプリケーションデータを分離し、アプリケーションDBでは内部ユーザーIDを使用する。

## 将来拡張

- Expo / React Native から共通ロジックを再利用する。
- OCRやAIの処理結果を、原本、抽出結果、ユーザー修正、最終確認状態に分けて扱う。
- モデレーション、法的保全、監査ログ、データエクスポートを追加できる設計にする。

## 公開前対応

- Supabase RLS の設計とテスト
- 環境変数と秘密情報管理
- 本番・開発データ分離
- バックアップと復元テスト
- 費用上限と停止手順
