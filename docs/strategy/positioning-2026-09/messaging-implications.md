# Messaging Implications: MECHORI
*Skill: startup-positioning | Generated: 2026-09-22*

## Messaging hierarchy

1. **Outcome:** 次の整備で、愛車の説明をゼロからやり直さない。
2. **Category:** 工場へ持ち運べる、愛車の整備履歴パスポート。
3. **Mechanism:** 過去整備と今回の相談を渡し、今回の作業結果を履歴へ戻す。
4. **Control:** 見せる範囲はOwnerが選び、共有は停止できる。届いた内容はOwner確認後に履歴へ入る。
5. **Long-term context:** 許諾された経験を、次のOwnerとWorkshopへ生かす。

Do not place the Knowledge Network or Professional Network above the immediate Owner outcome.

## Exact category label

**Always use in the entry context:**

> **愛車の整備履歴パスポート**

**Always explain with:**

> **工場へ持ち運べる整備履歴**

Use “愛車パスポート” alone only after the context has already established maintenance history and Workshop use.

## Primary value promise

> **過去の整備を次の工場へ渡し、今回の整備を次回へ残す。**

Supporting outcome:

> **入庫のたびに、愛車の説明をゼロからやり直す負担を減らす。**

This language describes an outcome to test. It does not guarantee that a Workshop has read the record or that the history is complete.

## Customer language vs. category language

| Customer verbs / questions | Category nouns / outcomes |
|---|---|
| 前に何をしたか見せる | 整備履歴 |
| 工場に伝える | パスポート / 共有 |
| 明細や写真をまとめる | 愛車ごとの履歴 |
| 今回やったことを残す | 作業結果 / 次回へ残る履歴 |
| 次の工場でも使う | 持ち運べる / 継続 |

Bridge example:

> 前に何をしたかを工場へ見せ、今回やったことを次回へ残す。愛車の整備履歴パスポート。

## Words to use and avoid

| Use | Avoid | Why |
|---|---|---|
| 整備履歴 | データ資産 | Concrete Owner language |
| 工場へ見せる / 持ち運ぶ | クロスステークホルダー連携 | Describes the job |
| 届いた内容を確認して追加 | 工場確認済み | Sender is not verified in current α |
| 過去の作業 / 今回の結果 | Evidence Graph / Knowledge Graph | Internal architecture is not entry positioning |
| 原因候補 / 確認箇所 / 改善報告 | 原因 / 必ず直る / 修理方法 | Maintains safety boundary |
| 許諾された経験 | 世界最大の整備データ | Network scale is unproven |
| 長期構想 / 仮説 | まもなく / 実現済み | Separates vision from fact |

## What not to lead with

- 自動車SNS.
- 整備士のGitHub.
- 整備Knowledge Network.
- AI故障診断 or AI assistant.
- Vehicle history service.
- Workshop management / CRM / DMS replacement.
- Resale value or verified history.
- “Global network” before local roundtrip behavior is demonstrated.

These can attract the wrong comparison, buyer, or trust expectation. The long-term network story belongs after the Owner understands the Passport loop.

## Channel implications

### Owner landing / invitation

Lead with the next real Workshop visit and a single vehicle. Show “past goes out / result comes back” in one compact sequence.

### Workshop link

Do not sell MECHORI first. State that this is the Owner-shared current concern and past maintenance for the vehicle, then make the requested return action obvious.

### Professional teaser

Frame MECHORI as receiving customer vehicle context and returning a clear work result—not as replacing the Workshop's system or giving diagnostic authority.

### Community / social

Use the hobby-car context for relevance, but do not make likes, feeds, or public posting the category.

## Social-proof guidelines

No public proof claim exists yet for reduced explanation, faster intake, Workshop acceptance, or later reuse. Do not invent quotes or convert α feedback into a generalized testimonial. Collect exact, permissioned language only after the live experiment.

## Data gaps

- Which phrase—“持ち運べる,” “引き継げる,” or “次の工場へ”—produces the clearest unaided restatement.
- Whether Workshops prefer “過去整備履歴,” “入庫情報,” or another local term.
- Whether “愛車” narrows the category helpfully or sounds too enthusiast-only in later markets.

## Confidence

**Medium** for the hierarchy's consistency with the product; **Low-to-Medium** for resonance until the α positioning experiment is run.

## Red Flags

- Leading with future Knowledge or Professional value makes present value harder, not easier, to understand.
- “Verified,” “complete,” and “health” create unsupported trust claims.

## Yellow Flags

- Outcome copy must not conceal the Owner's setup effort or Workshop's choice not to use the link.
- The category label may require local-market adaptation.
