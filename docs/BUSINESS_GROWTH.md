# BUSINESS_GROWTH

## 文書の目的

MECHORIを、作って終わるプロトタイプではなく、使われ、知識が増え、継続収益を生む事業へ育てるための検証順序を定義します。

人数だけを追うのではなく、次の循環が成立しているかを見ます。

```text
車両を登録する
  -> 整備記録またはJournalを残す
  -> 本人へ履歴整理・共有・工場提示の価値が返る
  -> 確認済み情報が車種別ナレッジになる
  -> 症状検索が出典付きの手掛かりを返す
  -> オーナーや工場が次の記録・結果を追記する
```

## 現在の未検証仮説

以下は成長の作業仮説であり、`docs/CONSTITUTION.md`に定める確定原則ではありません。P0 / Founder Test、M1 / Closed Alpha、M2 / Invite Beta、Professional実証の結果によって、変更、縮小、棄却します。

### A. 個人価値ループ

```text
愛車と過去記録を登録する
  -> 履歴が時系列に整理される
  -> 振り返り、追記、工場提示、出力へ再利用する
  -> 自分のために次の記録を残す
```

一人でも成立させる最優先ループです。P0 / Founder Testでは、履歴が育つ喜びと、次に使う具体的な場面が生まれるかを確認します。

### B. 集合知ループ

```text
オーナーや工場が実例を残す
  -> 確認済み部分が車種・世代・仕様別に整理される
  -> 他の利用者が検索・参照する
  -> 追加情報、訂正、結果が戻る
  -> 集合知の適用範囲と確度が高まる
```

同車種の経験が増えるほど利用者へ価値が返るという仮説は有力ですが、現時点では未検証です。車種別ダイジェスト、ナレッジ密度、ワンタップ回答等は、このループを検証する手段の候補であり、必須機能ではありません。

### C. 招待ループ

```text
車種や症状について不足している経験が見える
  -> その経験を持つ具体的な人を思い出す
  -> 個別に招待する
  -> 新しい実例や結果が追加される
  -> 招待した本人と車種コミュニティにも価値が返る
```

ポイントや招待人数ではなく、欠けた経験を持ち寄ることが招待動機になるという仮説です。P0 / Founder Testだけで一般化せず、招待したい具体的な相手が自然に挙がるかを観察し、M2 / Invite Betaで車種密度を含めて検証します。

### D. 市場価値ループ

```text
整備・故障・部品・結果の履歴を継続して残す
  -> 修理時の説明と判断材料に再利用できる
  -> 譲渡・販売時に、許可した履歴を提示できる
  -> 履歴のある車両への信頼が高まる
  -> 購入後も次の利用者が履歴を続ける
```

「MECHORI履歴あり」が中古車販売や譲渡時の信頼材料になることは、将来像および事業仮説です。車両状態、整備品質、走行距離、資産価値をMECHORIが保証する表現ではありません。

市場での受容、履歴の真正性、権利、責任、訂正、移管方法を検証するまで、保証や認証を想起させる名称は採用しません。

### 検証候補

- FIAT Barchettaを密度アンカーとした同車種実証
- 車種別の週次・月次ダイジェストを手作業で提示する実験
- 車種・仕様・症状ごとの不足経験の表示
- 整備明細、交換経験、症状経験、ワンタップ回答からの実例化
- プライバシー確認済みの愛車履歴・車種サマリー共有

これらは実装予定一覧ではありません。小さな実験で本人価値、再訪、招待、情報品質を確認した後に、実装の要否を判断します。

## Evidence Loopと長期North Star候補

MECHORIの長期価値は、投稿件数だけでなく、次の循環が閉じることにあります。

```text
記録
  -> 整理・Evidence化
  -> 検索・閲覧・再利用
  -> 実際の対応・作業
  -> 結果・再発の追記
  -> 次の利用者が再利用
```

この循環を`Evidence Loop`と呼び、月内に再利用から結果追記まで確認できた`Monthly Completed Evidence Loops`を長期North Star候補とします。ただし現α3〜5人では母数とKnowledge密度が小さく、これだけを唯一の経営指標にはしません。Quick Record成功、再投稿・再訪、post-save enrichment、Evidence化、他者記録閲覧、Meaningful Reuse、結果追記、投稿後の削除・後悔等をLeading Indicatorとして観察します。定義と昇格条件は`docs/MEASUREMENT_PLAN.md`を正とします。

## 整備記録の確認状態

確認状態は、身分証明書等による本人確認やKYCとは区別します。現時点では用語と測定対象を整理するものであり、詳細なデータモデルや実装方式は確定しません。

- `利用者確認済み`: 入力した利用者自身が、記録内容を確認した状態
- `資料確認済み`: 整備明細、記録簿、領収書等の資料によって内容を確認した状態
- `工場確認済み`: 実際に作業した工場または担当者が、記録内容を確認した状態
- `未確認`: 記憶、推測、AI抽出候補等を含み、裏付けが完了していない状態

一つの記録に複数の確認根拠が関係する可能性があります。この文書の初期目標で記録件数を測る場合は、特記がない限り、少なくとも`利用者確認済み`である記録を対象とします。`資料確認済み`と`工場確認済み`は、より強い裏付けとして別途観察します。

## 北極星

愛車趣味を、より長く、維持しやすく、始めやすくします。

初期市場は、旧車、希少車、趣味性の高い車両など、知識不足や地域差の影響を受けやすい領域です。ここから始めますが、現行車、カスタム車、チューニング車への将来展開を否定しません。

事業上の北極星指標は、単純な登録者数ではなく、次の複合指標を使います。

- **記録のある実車両数**: 1件以上の利用者確認済み整備記録を持つ車両
- **再利用された履歴数**: 検索、工場提示、出力、共有のいずれかに使われた履歴
- **根拠付き検索成功率**: 検索時に、車両一致範囲を示した出典へ到達できた割合
- **結果追記率**: 未解決記録に、その後の確認・対応・結果が追記された割合
- **維持可能車種密度**: 対象車種の主要な症状・部品・作業テーマを、独立した実記録でどこまで覆えているか

MAUを継続性の母数にします。価値への到達を示すValue Reach MAUは導線診断に使い、価値の利用・蓄積を示すValue Action MAU、`Value Action MAU / MAU`、`3-month Value Return`を継続的な価値利用の主要指標にします。DAUや投稿件数は診断用の補助指標です。整備は毎日起きないため、日次利用や連続ログインで価値を判断しません。各指標の定義は`docs/MEASUREMENT_PLAN.md`で管理します。

Professionalでは、第一線の整備士が同業者へ自発的にMECHORIを勧める状態を長期の定性指標にします。ただし推薦コメントや著名人の参加だけを成果にせず、紹介された整備士について、案件記録の再利用、結果追記、技術ポートフォリオ公開、有償相談、3か月継続利用のいずれが成立したかを測ります。

## 初期市場と検証対象

### ProductはUniversal、GTMはClustered

Productは、希少車、並行輸入車、限定車、グレード不明、catalog未登録を含め、すべてのクルマ・バイクが登録を開始できるUniversal設計を維持します。

一方、GTMでは初期Knowledge密度を作るため、2〜3程度の車種・近接車種・利用目的・community clusterへ獲得を集中させる実験を行います。100人が100車種へ完全分散した状態だけでは、同じ症状、部品、型式、対処のMeaningful Reuseを観察しにくいためです。これは登録制限や対応車種限定ではなく、acquisition strategyです。

### 初期検証の対象構成

- M1 / Closed Alphaの参加者は最初から複数車種であり、FIAT Barchettaだけに限定しない。
- 10〜20人、10車種以上、20〜30台を目安に、旧車・現行車、国産・輸入、DIY・工場依頼、クルマ・バイク、単数・複数台を含める。
- どの車種でも使われる記録・Journal・愛車プロフィールと、特定層で強く使われる検索・部品・工場提示を分けて観察する。
- FIAT Barchettaは所有者自身が実記録と検索密度を深く検証する「密度アンカー」とするが、M1 / Closed Alpha全体の対象車種にはしない。

### M1後に選ぶ2〜3クラスター

- M1 / Closed Alphaの再訪、記録、検索、共有、招待から、反応が強い利用目的または車種群を選ぶ。
- 例として輸入旧車、国産趣味車、DIY、工場整備中心、複数台管理等を比較する。
- 友人に同車種または似た使い方の知人を招待してもらい、自然に生まれた小さな集団でナレッジ密度を上げる。
- M1中もUniversalな登録体験の検証と並行して、候補clusterへ意図的に招待を寄せ、密度による再利用差を観察できる。効果が確認できなければ固定戦略にしない。

### 将来の展開候補

- ターゲットを車齢だけで切らず、車両の状態・履歴・変更内容を把握したい関わりの深さで広げる。
- 旧車・希少車から始め、スポーツカー、カスタム車、サーキット利用、現行チューニング車へ段階的に展開する。

### クルマとバイクの初期対応

- 初期からクルマとバイクの両方を登録可能にする。
- クルマとバイクをまたいだ複数台所有を扱えるようにする。
- 愛車プロフィール、Journal、写真、近況、整備履歴、費用、部品、工場記録など、共通化できる基本体験は両方で利用可能にする。
- バイクの参加台数をM1 / Closed Alphaの必須ノルマにはしないが、参加を除外または抑制しない。
- 車種、メーカー、仕様がマスタに存在しなくても、自由入力等で登録を止めない。
- 四輪と二輪で異なる故障分類、部品分類、安全警告、法制度、車両識別、仕様項目は、無理に初期から完全共通化しない。
- 二輪固有の専門的な検索、集合知、AI整理、安全ルールは、実際の参加車両と記録を見ながら段階的に検証、拡張する。

基本的な車両、履歴、コミュニティ体験は初期からバイクに対応しますが、二輪固有の専門機能まで初期から完全実装するとは決めません。

## 初期100人の獲得仮説

不特定多数への広告より、濃い車種コミュニティから始めます。人数配分は目標であり、同一人物を複数経路へ重複計上しません。

| 経路 | 目安 | 提供する入口 |
| --- | ---: | --- |
| 所有者の友人・既存の多車種の車仲間 | 20人 | 愛車プロフィール、履歴、Journal、工場提示 |
| M1 / Closed Alphaで反応が強かった2〜3クラスター | 30人 | 同車種・似た用途の知人招待、車種別ナレッジ |
| 協力整備工場・専門店からの紹介 | 20人 | 過去履歴の整理、工場との情報共有 |
| 公開Journalと安全な共有カード | 20人 | 読み物から車種・記録ページへ流入 |
| 検索・紹介・待機リスト | 10人 | 症状検索、対象車種追加の希望登録 |

許諾のないコミュニティ投稿の転載は行いません。管理者へ提携を依頼する場合も、元コミュニティを置き換えるのではなく、本人の記録整理と元投稿への導線を提案します。

## 段階別マイルストーン

数値は最初の仮説です。実利用で更新しますが、結果が悪いときに定義を緩めて合格扱いにはしません。

### P0 / Founder Test: 所有者本人と友人5人程度

対象: プロジェクト所有者本人と友人5人程度

目標:

- 実在する1車両へ10件以上の整備イベントを登録できる。
- 工場提示、履歴出力、検索、Journalのうち2つ以上を本人が再利用する。
- 過去資料1件の入力に必要な時間と、修正が必要な項目を計測する。
- 代表的な5検索で、情報不足を隠さず出典へ辿れる。
- 友人が説明なしで車両登録と最初の記録を完了できるか確認する。

合格条件:

- 「入力したデータを後で使う」具体的な場面が1つ以上ある。
- 手入力だけでは継続困難な箇所と、OCRが本当に必要な箇所を説明できる。
- 操作性と、本人の履歴整理による初期価値を説明できる。

### M1 / Closed Alpha: 10〜20人、20〜30台

目標:

- 10車種以上、20〜30台の実車両を目安とする。
- 利用者確認済み整備記録50件以上。
- 10件以上のJournalまたは共有された履歴節目。
- 登録後7日以内に、60%以上が車両登録と最初の記録・Journalのどちらかを完了。
- 30日以内に、40%以上が2回目の記録、検索、閲覧、共有のいずれかを行う。
- 暦月ごとのMAU、Value Reach MAU、Value Action MAUを人数で記録し、利用者への聞き取りで戻った理由を確認できる。
- 自発的な改善要望または「次に使う具体場面」を10件以上集める。

合格条件:

- 5人以上が、依頼されなくても2回目の利用をする。
- DIY以外の工場整備ユーザーからも、履歴整理または工場提示の価値が確認できる。
- 複数ユーザーがいる状態で、履歴整理、閲覧、共有の継続価値を説明できる。
- 車齢、国産・輸入、DIY・工場依頼等の比較から、次に密度を上げる2〜3クラスターを説明できる。
- 重大なプライバシー事故、安全上の誤解、運営不能な通報負荷がない。

### M2 / Invite Beta: 100人規模

目標:

- 登録100人、記録のある実車両70台。
- 利用者確認済み整備記録300件。
- 公開可能なJournalまたはナレッジ100件。
- 主要な30症状・整備テーマについて、情報の有無を明示できる。
- 検索後評価で50%以上が「次に確認する手掛かりになった」と回答。
- 90日以内に30%以上が記録、検索、Journal閲覧・作成、工場提示のいずれかへ再訪。
- Value Action MAU Rate 60%以上を仮目標とし、`3-month Value Return`を観察する。
- 車種コミュニティと、不足経験を持つ人への招待ループを検証する。

合格条件:

- 1つ以上の獲得経路から、毎回の個別勧誘なしに新規利用が発生する。
- 10人以上がOwner Plus候補機能に支払意向を示す。
- 3拠点以上の工場がProfessionalの実タスク検証へ参加する。

### M3: 初期収益化検証

目標:

- Owner Plus有料実証10人。
- Professional有料または有償実証3拠点。
- 1人・1拠点当たりのAI、OCR、Storage、サポート原価を把握する。
- 解約・継続理由を全件確認できる小さな運用を維持する。

合格条件:

- 3か月継続後も、売上総利益が正である。
- 支払理由が応援ではなく、複数車両の高度な整理・比較、未登録車種検索、入力省力化、業務調査等の反復価値に結び付く。登録台数の解放自体は購入理由にしない。
- 運営者の個別作業が増えるほど赤字になる構造ではない。

### M4: 成長投資判断 1,000人

目標:

- 登録1,000人ではなく、記録のある実車両と検索再利用が継続増加している。
- 複数車種でM2相当のナレッジ密度を再現できる。
- 有料継続率、サポート工数、モデレーション負荷、インフラ原価を月次で確認できる。

この段階で初めて、広告、一般公開地域の拡大、ネイティブアプリ、採用、外部資金等を比較します。

## 測定するファネル

### 獲得

- 招待リンク・紹介元ごとの登録数
- Journal共有、車種コミュニティ、工場紹介、検索流入の区別
- 招待から登録までの日数

### 初回価値

- 車両登録完了率
- 最初の整備記録またはJournal作成率
- 過去記録の追加件数
- 工場提示、出力、共有、検索まで到達した割合
- オーナー全体、個別車両、車種のどの単位をフォローしたか

### 継続

- 2回目の記録・検索・閲覧・共有までの日数
- 30日と90日の意味のある再利用率
- MAU、Value Reach MAU、Value Action MAU、Value Reach MAU Rate、Value Action MAU Rate、`3-month Value Return`
- 月内に戻った理由の内訳: 愛車履歴、未解決追記、検索、フォロー更新、Journal、工場提示
- 未解決記録への結果追記率
- 車種別の記録密度
- 車齢だけに依存しない利用クラスター別の再利用率

### 収益

- 機能別の支払意向
- 価格提示後の有料実証参加率
- プラン別継続・解約理由
- 利用者別の変動原価とサポート時間

分析のために不要な個人情報、正確な位置、広告識別子を増やしません。初期はサーバー分析SDKを導入せず、必要なイベント定義だけを作ります。

## 収益化の順序

1. 無料のClosed AlphaおよびInvite Betaで記録価値、Evidence化、再利用を確認する。
2. 部品購入意図が自然に存在する箇所で、AffiliateがConsumer基盤原価の一部を補填できるか小さく検証する。
3. AI無料枠の実利用量と原価を測り、超過枠は原価回収を主目的として必要になった時点で検証する。
4. Owner Plus候補の処理量や高度機能へ実際に到達した利用者へ、価格を明示して補助収益を検証する。Evidence supplyを阻害する登録台数制限は採用しない。
5. 3拠点程度の工場で、Professionalの一つのEvidence workflow、時間短縮、手戻り、顧客説明、支払意向を検証する。
6. 原価と継続率が成立してからProfessional SaaS、Network、Knowledge Infrastructureを段階的に検討する。
7. 広告は、十分な閲覧量とプライバシー・同意・収益試算が揃ってから判断する。

Professionalは長期的な主収益候補ですが、現αのGTMを営業型B2Bへ依存させません。人数が少なくても単価と課題が明確になり得るため広告より先に実業務を観察しますが、Knowledge Searchだけを販売せず、工場単独でも成立するEvidence workflowを確認します。

## Professional獲得

Professional LPは、営業を不要にするものではなく、説明、信頼確認、価格提示、相談受付を代行して初期営業を短くするものと位置付けます。

初期3〜10拠点は、次の順序で獲得します。

1. オーナーが普段利用する工場へ、本人の履歴サマリーと工場提示画面を見せる
2. 工場提示画面から、車両情報を含まないProfessional紹介文を共有する
3. 実案件の受付、記録、作業報告を一緒に試す
4. Founding Garageの参加条件と、正式Professionalとは別の契約条件を提示する
5. 協力工場から同じ課題を持つ工場を紹介してもらう

LPでは、機能一覧よりも、受付、作業、顧客報告、履歴引き継ぎの一連の流れを示します。工場内限定、対応経験シグナル、許諾ナレッジの違いも表示し、知識の無償公開を要求するサービスだと誤解させません。

価格、収入目標、国際展開を含む詳細は`docs/BUSINESS_MODEL.md`を参照します。

## Drive Engagement / Acquisition（Future Measurement Hypothesis）

Drive Recordは、整備の発生頻度が低いOwnerにも再訪理由を作り、Vehicle Experienceを増やし、外部共有から新規獲得へつなげるsub-system候補として検証する。DriveをNavigationやroute recommendationの利用量で評価せず、記録されたExperienceとEvidenceへの循環で評価する。

将来指標候補は、Drive Session作成数、共有数、Public Share閲覧数、未ログイン閲覧からのsignup、再度Driveを記録した割合、DriveからExperienceEntryが追加された割合、後日のIssue / Maintenance / Result linkageである。現αのKPIへは追加せず、Native・Public Shareを実装する前の仮説として扱う。

SNS共有は個別SNS APIを前提にせず、Public URL、OGP、OS Share Sheet、share-friendly previewで成立するかを先に検証する。共有閲覧が増えてもVehicle Recordや再訪へつながらない場合、SNS機能を拡張する前にProduct valueとShare Pageを見直す。

## 失敗時の判断

- 車両登録後の最初の記録作成が40%未満なら、集客を増やす前に初回入力と本人便益を見直す。
- 記録は作られるが再利用されないなら、履歴サマリー、工場提示、検索、リマインドの価値を見直す。
- 検索の大半が情報不足なら、AIを強くするのではなく、対象車種を絞って実記録を集める。
- Journalだけが伸び、整備情報が構造化されないなら、利用者による確認を保った候補抽出と追記導線を改善する。
- Quick Recordは増えるがpost-save enrichmentや結果追記へ進まないなら、投稿前入力を増やさず、保存後の任意導線と本人へ返る価値を見直す。
- α共有固定で投稿後削除、公開範囲変更希望、写真公開への不安が続くなら、正式公開まで固定共有を一般化せずUser Controlを再検討する。
- Professionalで調査時間が短縮されないなら、顧客管理等を増やす前に、検索対象・出典・車両一致の品質を見直す。
- 有料意向が応援に偏るなら、価格や機能を確定せず反復利用される便益を探す。

## Public Share / OGP Acquisition（将来仮説）

Public Share / OGPは、MECHORI brandを広告するためではなく、Userが共有したVehicle / Experienceへの関心から未Userの閲覧、signup、beta invitationへつながるAcquisition Surfaceとする。将来はshare view、未ログイン閲覧、shareからのsignup interest、Public Shareからの再訪を検証候補にするが、現αのKPIには追加しない。

通常ExperienceではUser contentを主役にし、branded cardの露出を強めることをGrowth施策の前提にしない。Drive-specific route imageは将来仮説であり、共有価値とPrivacyの両方を人間QAで確認する。

## 不正インセンティブを避ける

- 投稿件数、閲覧数、フォロワー数へ金銭、検索順位、信頼ラベルを直接結び付けない。
- History Levelは本人の整理状況であり、情報の正確性や整備能力を示さない。
- バッジは出典追記、結果更新、訂正協力等を評価できるが、主張の真偽は別の確認状態で示す。
- 紹介施策を行う場合も、安全審査や公開確認を省略する特典を与えない。

## 所有者側の長期構想

MECHORIの利益を蓄積し、将来、室蘭へ人と資金を呼ぶ事業や場所へ再投資する構想があります。この目的は事業を長く続ける動機として保持しますが、初期の法人所在地、税務、寄附方法を先に固定して製品検証を歪めません。収益が具体化した時点で、最新制度と事業実態を確認します。
