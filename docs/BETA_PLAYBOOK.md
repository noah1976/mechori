# BETA_PLAYBOOK

## 文書の目的

遠隔αを完了した後、SNSでつながる10〜20人を、登録者数を増やすためではなく、MECHORIの記録価値、検索価値、楽しさ、安全性を一緒に確認する協力者として迎える手順です。外部募集の開始、送信文面、公開URLは所有者承認後に使用します。

3〜5人の遠隔αについては`docs/ALPHA_PLAYBOOK.md`を参照します。αで重大な権限、データ消失、公開範囲、日本語、診断誤認の問題が残っている間は、β募集を開始しません。

## ベータの範囲

- 日本中心の招待制
- 友人・知人の多車種を対象にし、FIAT Barchettaは所有者自身の密度検証に使う
- 日本語UIを主に使い、英語表示の崩れも確認
- 無料。決済、広告、外部AI診断は導入しない
- 公開ナレッジ候補は運営確認を通す
- 実画像・動画は公開用マスキングが完成するまで非公開

## 参加者構成

同じタイプだけで固めません。重複して構いませんが、次を含めます。

| タイプ | 目安 | 確認したいこと |
| --- | ---: | --- |
| 旧車・輸入車・希少車 | 5人以上 | 情報不足、車種固有検索、部品履歴 |
| 国産趣味車・現行車 | 3〜5人 | 旧車以外でも記録・カスタム共有が続くか |
| 工場整備中心のオーナー | 5人以上 | 承認欲求以外の入力価値、工場提示 |
| DIYも行うオーナー | 3〜5人 | 作業記録、Journal、出典追記 |
| クルマとバイク、または複数台持ち | 2〜3人 | 複数台の記録・車両切替・Evidence contribution。固定台数制限は初期保留 |
| 文章投稿が苦手な人 | 3人以上 | 整備記録だけで成立するか |

WebサービスやITに詳しい友人だけを集めません。

## 募集経路の順序

1. 遠隔αへ参加した特に親しい友人3〜5人
2. SNSでつながる、異なる車種・用途を持つ知人とオーナー仲間
3. 協力工場から紹介されたオーナー
4. 許可を得た車種コミュニティ

αの3〜5人で重大な入力・プライバシー問題を直してから、10〜20人へ広げます。SNSへの一般募集や不特定多数が使える共通招待コードは使用しません。

## 募集文の下書き

```text
旧車や輸入車の整備記録を、自分の履歴として残しながら、同型車の知識として役立てるサービス「MECHORI」を試作しています。

完成したサービスの宣伝ではなく、10〜20人で使い勝手を確認する招待制テストです。整備記録だけでも、故障や路上停止を含むGarage Journalを書いても構いません。

MECHORIは故障診断や修理指示を行いません。実在する整備情報を公開する場合は内容を確認していただき、画像・個人情報は安全な処理が整うまで非公開で扱います。

30分ほど試して、分かりにくかった点を率直に教えてもらえる方を探しています。
```

「あなたの投稿で誰かを救える」だけを前面に出さず、自分の履歴整理、工場提示、読み物としての楽しさを伝えます。

## 初回セッション

目安は30分です。運営者は説明しすぎず、詰まった場所を観察します。

1. ベータ範囲、安全性、非公開初期値を説明する。5分
2. 自分の車両を1台登録する。5分
3. 過去の整備を1件、またはJournalを1件残す。10分
4. 自分の車種で症状検索を試す。5分
5. 履歴サマリーまたは工場提示を見る。3分
6. 率直な感想を聞く。2分

操作を代行しません。助けが必要になった時点と質問内容を記録します。

## 観察項目

- 最初に何のサービスだと思ったか
- 車両登録で分からない項目
- 整備記録とJournalのどちらを選んだか、その理由
- 工場整備の人が「入力する意味」を感じた場面
- 非公開、公開候補、運営確認の理解
- 症状検索を診断だと誤解しなかったか
- 出典、一致範囲、情報不足が理解できたか
- 写真・動画公開への不安
- もう一度使うとすれば、どの場面か
- 人全体と個別車両のどちらをフォローしたいか
- 車齢・所有歴を見せたいか、どの範囲なら公開できるか

## 初回インタビュー

誘導を避け、過去の実際の行動を聞きます。

- 最後に整備記録を探したのはいつで、どこにありましたか。
- 工場へ過去履歴を説明するとき、何が面倒でしたか。
- 最近、同型車の情報をどう探しましたか。
- 見つからなかった情報は何でしたか。
- 故障や修理をSNSへ投稿したことはありますか。なぜ投稿しましたか。
- 今日入力した内容を、次にいつ使いそうですか。
- 使わないとしたら、最大の理由は何ですか。

「欲しいですか」より、実際に起きた行動と次の具体場面を優先します。

## 7日・30日の確認

### 7日後

- 最初の記録以外を追加したか
- 履歴、検索、Journalを再度開いたか
- 入力を後回しにした理由
- 公開または共有したい内容があったか

### 30日後

- 実際に再利用した場面
- 未解決記録へ結果を追記したか
- 友人へ紹介したか、または紹介しなかった理由
- 有料候補機能のどれに反復価値を感じるか

連絡頻度と方法は参加時に同意を得ます。反応がない人へ繰り返し催促しません。

## Founding Memberの扱い

- 創設協力への表示や記念バッジは検討できる。
- 投稿件数、フォロワー、人気へ報酬を結び付けない。
- バッジは情報の正確性、整備能力、車両状態を保証しない。
- 安全審査や公開確認を省略する権限を与えない。
- 有料版無償期間等は、価格検証を歪めるためM1では約束しない。

## 問題発生時

- 個人情報・ナンバー・顔等の公開懸念: 即時非公開にし、原本と派生データを確認する。
- 危険な整備情報: 公開を止め、安全担当・専門家確認へ回す。
- 誹謗中傷・工場評価: 非公開化し、事実確認とモデレーション記録を残す。
- データ削除希望: 本人確認後、対象データと外部処理先を確認して削除する。
- 診断と誤解: 表示と説明を修正し、同じ誤解が他の参加者にも起きていないか確認する。

## M1終了判定

`docs/MEASUREMENT_PLAN.md`の指標に加え、次を確認します。

- 5人以上が依頼なしで2回目の利用をした。
- 工場整備中心の利用者にも本人価値があった。
- 運営者が毎回入力や説明を代行しなくても使えた。
- 深刻な安全・プライバシー事故がなかった。
- 共通価値と特定層だけの価値を分け、次に密度を上げる2〜3クラスターを判断できた。

合格しなくても人数を増やして押し切らず、初回体験、入力、履歴価値、対象車種を見直します。
