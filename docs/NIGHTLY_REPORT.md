## 今回の目的

Garage Journalのnote型編集と根拠付き検索を維持しつつ、ミュート・ブロック・解除管理と、未ログインから招待登録・ログイン・ログアウトまでのローカル認証モックを追加しました。併せて、国ごとに異なる整備記録PDFの取込方針と、本番認証候補を整理しました。

## 実施したこと

### Journal編集

- 段落、見出し、引用、写真、動画を順序付きブロックとして保持します。
- 各ブロックの間から文章・見出し・引用・写真・動画を挿入できます。
- ブロックの上下移動、削除、メディア説明を操作できます。
- AIは本文を生成・書換えしません。
- Journalを書かず「整備記録だけ残す」導線を同じ画面に用意しました。
- 旧Journal本文は試作スキーマv5への移行時に段落ブロックへ変換します。

### ホーム

- 故障や路上停止も愛車の物語として読まれることを主題にしました。
- 「今日のことを書く」「整備記録だけ残す」「みんなの経験から調べる」を同じ第一画面へ配置しました。
- フォロー中のJournalを画像付きで主表示し、最近の整備記録は別領域へ維持しました。

### ナレッジ検索

- DEMO事例だけから、確認箇所、原因候補、対応、交換部品、結果を自然文と項目別表示へ整理します。
- 要約の下に、車両一致範囲と確認状態を添えた出典投稿リンクを表示します。
- 出典にない内容を追加しない共通契約と根拠検証テストを追加しました。
- 検索条件が空の間は回答を生成せず、情報不足状態を表示します。
- 自分の非公開整備記録は要約と分離して表示します。

### 表示と安全

- プロフィール単位のミュート、ブロック、解除管理を追加しました。
- ミュートはフォロー状態を保ったまま対象者の投稿をフィードから隠します。
- ブロックは対象プロフィールと個別車両へのフォローを解除し、投稿、候補、直接Journal閲覧を抑止します。車種フォローは維持します。
- Journal直接URLにも、非公開、フォロワー限定、ブロックの閲覧判定を適用しました。
- 旧データを失わず、localStorage試作スキーマv8へ移行します。

### 次段階の準備

- 整備記録PDFは国・言語・発行元・年代ごとに異なる前提とし、未知様式を無理にテンプレート確定しない方針を追加しました。
- 招待URLをSNSで送り、初期はGoogleログイン中心、Apple・X・メールは後段とする方針へ更新しました。
- 認証Provider、Supabase、メール送信には接続していません。

### 認証・未ログイン表示

- Google、Apple、Facebook、X、メールを選べるProvider非依存のローカル認証モックを追加しました。
- 新規登録はDEMO招待コードを必要とし、入力したメールアドレスは保存しません。
- 未ログインでは公開ホーム、公開ナレッジ検索、公開Journalだけを表示します。
- Garage、フィード、整備履歴、入力画面はログインへ誘導し、認証後に元の画面へ戻します。
- ログアウト後は公開ホームへ戻り、非公開Journalの直接URLも表示しません。
- 認証状態が未保存・不正な場合は未ログインを既定とし、外部URLや認証画面へ戻す特殊な`returnTo`を拒否します。
- 認証状態をブラウザタブ間で同期し、別タブでのログアウトや保存値削除時も未ログインへ切り替えます。
- 存在しないJournalは非公開Journalと分け、「ログインすれば閲覧できる」と誤案内しません。

### 下書き・保存リカバリー

- 整備記録とJournalの入力途中内容を、正式データと分離した端末内下書きへ自動保存します。
- 再読み込み後に復元でき、利用者が明示的に破棄できます。空フォームは下書きとして残しません。
- Journalは文章と設定だけを保持し、写真・動画本体は複製せず再選択が必要な件数を表示します。
- 本保存は端末への書込み成功後に画面へ反映し、失敗時は下書きを維持してエラーを表示します。
- 入力エラー時は先頭の問題項目へフォーカスし、非表示ファイル入力をキーボード・読み上げ対象から除外しました。

### 通報・公開範囲・画像プライバシー

- Journalを個人情報、危険な断定、嫌がらせ、権利侵害、スパム等の理由で通報でき、同じ利用者による対応中の重複を抑止します。
- 運営DEMOで、受付、確認開始、修正依頼、一時非公開、問題なし終了、復元と最小操作履歴を確認できます。
- 一時非公開をフィード、直接URL、ナレッジ候補へ適用し、削除とは分けました。
- プロフィールを自分だけ、直接フォロワー、公開から選び、役割、自己紹介、愛車、所有期間、公開Journal件数を項目別に設定できます。
- 画像確認DEMOを複数候補、誤検出、見落とし候補の手動追加、公開用派生画像、全体目視確認へ拡張しました。

## ディレクション判断

- 投稿の楽しさは装飾ではなく、知識が集まるための前提条件として扱います。
- ブログ本文を書く利用者と、整備記録だけを残す利用者を上下関係にしません。
- AI要約を回答の主表示としますが、投稿へのリンクを検証可能な根拠として必ず残します。
- 人気、フォロワー、リアクションは検索根拠の強さや確認状態に使用しません。
- ミュート・ブロック状態も公開評価へ使わず、利用者本人の表示安全設定として扱います。

## 外部接続・費用

- 採用前提のSupabase、Netlify、OpenAI APIと、候補のOCR Providerへ接続していません。
- 有料サービス、決済、広告SDK、アクセス解析を追加していません。
- 本番デプロイ、mainへの反映を行っていません。
