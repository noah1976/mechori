# PREVENTIVE_INSIGHTS

## 目的

車両の年式、確認できる走行距離、交換履歴、類似車両の実例から、次に確認する候補を出典付きで説明します。故障予測、交換命令、メーカー指定周期の代替ではありません。

## 表示する内容

- 対象車両の仕様と、参照した履歴
- 同一仕様、同車種別年式、共通部品等の一致範囲
- 類似事例で交換・点検が記録された年数または距離の分布
- 自車で確認できる前回交換日・表示走行距離
- 現在登録されている兆候の有無
- 「点検候補」「履歴確認候補」「情報不足」の区別
- 根拠となる事例、反対結果、未解決事例へのリンク

採用表現:

> 同型車の公開事例では、この時期に交換報告が増えています。現在の車両履歴だけでは交換要否を判断できません。過去の交換履歴がなければ、次回入庫時の点検候補です。

避ける表現:

- 「もう交換時期です」
- 「次に壊れる部品です」
- 「この部品を交換してください」
- 「この年式・距離なら必ず発生します」

## 入力データ

初期:

- 車種、年式、仕様
- 整備イベントと部品・作業
- メーターEpisodeごとの表示走行距離
- 解決、未解決、再発、反対結果

将来、本人が任意で追加できる候補:

- 年間走行量の大まかな範囲
- 街乗り、長距離、サーキット等の用途
- 屋内・屋外等の大まかな保管条件
- 国・州・都道府県程度の気候区分

正確な位置、常時GPS、住所、ナンバー、VIN全文は使いません。気候や用途は、価値とプライバシーを実利用で確認してから追加します。

## 走行距離の扱い

メーター交換、修理、リセット、桁あふれ、単位変更があり得ます。

- 現在表示値を累積走行距離とみなさない。
- Episodeをまたぐ大小比較だけで虚偽・異常と判定しない。
- 推定累積距離を使う場合は、計算根拠、範囲、確度を別に表示する。
- 根拠が弱い場合は、年式または交換からの経過年数だけを使う。

## 最低データ条件

初期公開では、最低件数を満たさないテーマを文章生成しません。具体的な閾値は実データで決めますが、少なくとも次を分けます。

- 単独のオーナー報告
- 複数だが同じ転載元の報告
- 独立した複数車両の報告
- メカニック確認済み情報
- メーカー・公的資料

CRITICAL領域では、オーナー投稿の分布だけで交換候補を推奨表示しません。専門家・整備書の確認と、情報不足の表示を優先します。

## Professional表示

Professionalでは簡略な結論より、判断材料を優先します。

- 事例分布と母数
- 車両仕様の差
- 確認された症状と未確認条件
- 交換で改善、変化なし、再発、未解決の内訳
- 部品番号の確認状態と互換根拠
- 出典資料と最終確認日

契約プランは情報の正確性や整備能力を保証しません。整備士が実車、整備書、法令と照合するための調査支援です。

## 実装順序

1. データ要件と禁止表現を固定する。
2. 実例分布を決定的に集計する。
3. 出典・反対結果付きの非生成UIで検証する。
4. 安全評価と最低件数を決める。
5. 最後に、同じ構造を文章化するProviderを追加する。

ナレッジ密度が不足する間は「情報不足」を正しい出力とします。
