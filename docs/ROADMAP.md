# ROADMAP

## Phase 0: 設計文書とルール整備

- `AGENTS.md` と `docs/` の初期文書を作成する。
- プロダクト、安全、プライバシー、法務、AI、収益化の基本方針を揃える。
- 未確定事項を `docs/BACKLOG.md` に整理する。

## Phase 1: 初期MVP設計

- データモデル案を作成する。
- 画面一覧と主要導線を定義する。
- 初期Webアプリ構成を決める。
- Supabase、Netlify、OpenAI APIの接続前に初心者向け手順書を作成する。
- 料金、無料枠、停止方法を確認する。

## Phase 1.5: 所有者自身で価値検証

- 実在する1車両の整備履歴を10件以上登録する。
- 履歴サマリー、工場提示、検索、Journalのうち2つ以上を再利用する。
- 実帳票を使い、入力時間、OCRが必要な箇所、確認負荷を測る。
- 代表検索で、根拠不足を隠さず出典へ辿れることを確認する。

## Phase 2: Web MVP 実装

- スマートフォン向けWebアプリを実装する。
- 匿名またはハンドルネームのアカウントを実装する。
- 写真中心の3分愛車登録、上品な登録完了、写真と一言の最初の出来事、車両時間軸、安全な共有URLを先に縦方向で完成させる。
- 愛車登録、整備イベント、作業の親子構造を実装する。
- 公開／非公開、検索、安全警告を実装する。
- 日本語／英語の基礎を実装する。
- Supabase Adapter、RLS、Netlify Previewを、外部接続承認後に段階導入する。

## Phase 3: 招待制ベータ 10〜20人

Phase 3へ進む前に、`docs/ALPHA_PLAYBOOK.md`に従って特に親しい友人3〜5人の遠隔αを実施します。Supabase Auth・RLS・期限付き個別招待・Netlify検証環境を使い、横で説明しなくても主要操作を完了できること、データ分離、再ログイン、日本語、診断誤認を確認します。

- 招待、初回体験、記録作成、再訪を最小限の指標で測る。
- 友人・知人の10車種以上、20〜30台を目安にし、本人確認済み記録50件を目標とする。
- FIAT Barchettaは所有者自身の密度アンカーとし、α全体を単一車種へ限定しない。
- オーナー全体、個別車両、車種のフォロー動機と、車齢・所有歴表示を検証する。
- 投稿確認、一時非公開、通報、削除理由を整備する。
- 利用規約、プライバシーポリシー、投稿ガイドラインを準備する。
- RLS、バックアップ、ログ、復元テストを確認する。
- 公開前レビューを行う。

## Phase 4: 車種コミュニティ検証 100人

- 記録のある実車両70台、本人確認済み記録300件を目標とする。
- 初回価値、30日・90日再利用、根拠付き検索成功率を確認する。
- 1つ以上の獲得経路で、個別勧誘に依存しない流入を確認する。
- Owner Plus候補の支払意向と、Professional実証へ参加する工場を確認する。

## Phase 5: AI/OCR 補助

- OCR結果の構造化補助を検討する。
- AIタグ候補、翻訳、重複候補、個人情報候補検出を検討する。
- AI出力を人間が確認してから保存する画面を実装する。
- キャッシュ、最大原価見積り、利用者別・月次ハード上限、非AI縮退を通過するProvider境界を実装する。

## Phase 6: 初期収益化検証

- Owner Plus有料ベータ10人を目安に、支払理由、原価、継続を確認する。
- Professional有料または有償実証3拠点を目安に、調査時間と受託判断への価値を確認する。
- 広告は初期収益源とせず、閲覧規模、プライバシー、同意、収益試算が成立してから判断する。
- 課金開始前に税務、価格表示、解約、返金、データ権利を確認する。

## Phase 7: 拡張

- 他車種・他メーカー・バイク等へ拡張する。
- メカニック確認済み情報を扱う。
- Expo / React Native 追加を検討する。
- 複数車種でナレッジ密度と獲得経路を再現する。
- 登録1,000人時点で、広告、一般公開地域、採用、外部資金を比較する。
- EU圏を含む次地域は、需要、ナレッジ密度、翻訳確認者、法務・運営体制を確認し、UI言語を段階追加する。

各段階の指標と合格条件は`docs/BUSINESS_GROWTH.md`を正とします。
