# USER_STORIES

## 文書の目的

MECHORYの初期MVPについて、利用者が達成したいことと受入観点を、画面・データモデル・実装タスクへ展開できる粒度で定義します。

初期公開は日本を中心とした少人数の招待制ベータです。初期MVPはFIAT Barchettaのオーナーを主対象とし、UIは日本語・英語に対応できる前提とします。メカニック向けの専門機能は将来市場ですが、初期ベータでは整備情報を探す利用者または事例提供者として参加できる範囲に留めます。

## 優先度と区分

- `P0`: 初期MVPの中心価値または安全な公開に不可欠
- `P1`: 初期ベータの検証を助けるが、限定的な手動運用でも代替可能
- `LATER`: 将来拡張。初期MVPには実装しない
- `RELEASE_GATE`: 一般利用者へ公開する前に必要。初期の内部検証では手動運用を許容する場合がある

## ペルソナ

### オーナー

FIAT Barchettaをはじめとする旧車・輸入車の所有者です。整備記録を残したい人と、車種固有の事例を探したい人を含みます。専門的な整備知識やデジタルサービスへの習熟は前提にしません。

### メカニック

車両の点検・整備経験を持ち、車種固有の事例を探す、または自身が確認した事例を提供する利用者です。初期MVPでは、資格・所属・専門性の認証や「メカニック確認済み」表示を自動的に付与しません。

### 運営者

招待制ベータの参加管理、公開候補の確認、訂正依頼、緊急非公開化を行うMECHORY運営担当者です。具体的な人数、役割分担、対応時間、エスカレーション手順は `NEEDS_OWNER` として別途決定します。

## オーナー向けストーリー

### US-OWN-001 招待制ベータへ参加する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、招待されたアカウントで安全に利用を開始し、自分の非公開領域へアクセスしたい。自分の車両と記録を他人に見られない状態で使い始めるため。
- 受入観点:
  - 招待されていない利用者が、招待制領域へ参加できない。
  - 認証情報とアプリケーションデータが内部ユーザーIDで分離される。
  - 初回利用時に、適用される利用規約・プライバシー方針の確認状態を記録できる。
  - ログイン方式をメール、パスワード、ソーシャルログイン等の特定方式へ固定しない。
- 未確定: 初期ログイン方式、招待の発行・失効・再発行方法。

### US-OWN-002 愛車を登録する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、自分の車両の一般的な仕様を登録し、その車両に整備記録と検索条件を関連付けたい。
- 受入観点:
  - FIAT Barchettaを登録できる。
  - メーカー、車種、年式等の主要項目を持ち、未確認の仕様は不明のまま保存できる。
  - VIN・車台番号全文、ナンバープレート、正確な保管場所を要求しない。
  - 車両情報の初期公開状態は非公開である。
  - 車種固有の分類粒度が未確定でも、架空の仕様を補完しない。
- 未確定: FIAT Barchettaの仕様分類粒度、MVPで登録できる車両数。

### US-OWN-003 整備イベントを手入力する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、1回の入庫または整備機会を記録し、その中に複数の作業をまとめたい。実際の整備履歴を後から確認できるようにするため。
- 受入観点:
  - 整備日、走行距離、症状、確認内容、原因候補、作業、部品、結果を、分かる範囲で登録できる。
  - 1つの整備イベントに複数の作業を関連付けられる。
  - 不明な項目を推測で埋めることを求めない。
  - 事実、推測、解決済み、未解決を区別できる。
  - 新規記録は非公開で保存される。
  - 部品番号等の安全上重要な文字列は、ユーザーが入力内容を確認できる。

### US-OWN-004 非公開の整備履歴を確認・訂正する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、自分の車両ごとに整備履歴を時系列で確認し、誤りや後から判明した結果を訂正したい。
- 受入観点:
  - 自分が閲覧権限を持つ車両と記録だけを表示できる。
  - 整備イベントと、その配下の作業を区別して確認できる。
  - 既存記録を訂正しても、公開ナレッジへ未確認の変更が自動反映されない。
  - 作成日時、更新日時、確認状態、訂正履歴を関連付けられる。
  - 他の利用者の非公開記録を閲覧・編集できない。

### US-OWN-005 同型車の事例を検索する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、症状、車種、年式、エンジン、部品番号、キーワードから関連する公開事例を探したい。自分の車両で確認すべき情報源を見つけるため。
- 受入観点:
  - 初期MVPで定めた検索軸から公開ナレッジを検索できる。
  - 自分の登録車両を検索条件として利用できる。
  - 完全一致がない場合、別年式・別仕様等へ範囲を広げたことを明示する。
  - 検索結果がない場合に、AIが架空の原因候補や修理方法を生成しない。
  - 検索結果と安全警告は課金の有無にかかわらず確認できる設計とする。

### US-OWN-006 事例の信頼性と安全性を判断する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、事例がどのような車両・出典・確認状態に基づくかを確認し、自分の車両へ適用できる情報かを慎重に判断したい。
- 受入観点:
  - 投稿者の経験、推測、AI整理、メカニック確認、公的資料等の情報種別を区別して表示できる。
  - 車種、年式、仕様等について、自分の車両との一致範囲を表示できる。
  - 解決・未解決、ユーザー確認状態、最終更新日、訂正の有無を表示できる。
  - MECHORYが診断・修理指示・安全保証を提供しないことを、事例利用の場面で確認できる。
  - 危険領域では危険度に応じた警告と専門家確認の案内を表示できる。
  - 安全情報の途中に広告を挿入しない。

### US-OWN-007 整備記録を共有候補にする

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、自分が確認した整備記録の一部を、同型車の役に立つ共有ナレッジ候補として明示的に提出したい。
- 受入観点:
  - 非公開記録が、ユーザー操作なしに公開候補または公開状態へ変わらない。
  - 共有する項目と共有しない項目を確認できる。
  - 個人記録とは別の共有ナレッジ候補を生成し、個人記録の正本を維持する。
  - 氏名、連絡先、住所、ナンバープレート、VIN・車台番号全文、原本等を共有対象にしない。
  - 公開前に内容、出典、確認状態、安全警告をユーザーが確認できる。
  - 提出後は運営確認中であることを識別でき、運営確認なしに公開されない。

### US-OWN-008 公開後の訂正・非公開化を申請する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、自分が共有した情報に誤りや公開上の問題を見つけたとき、訂正または非公開化を求めたい。
- 受入観点:
  - 対象の共有ナレッジを指定して訂正または非公開化の意思を伝えられる。
  - 安全上重大な問題では、通常の訂正待ちと区別して運営者へ伝えられる。
  - 申請中であることと、その後の状態を追跡できる。
  - 訂正履歴を保持しつつ、誤った旧内容を通常の検索結果へ出し続けない設計にできる。
  - 具体的な受付方法と対応時間は初期管理者運用で決定する。

### US-OWN-009 日本語または英語で基本UIを利用する

- 優先度・区分: P0 / 初期MVP
- ストーリー: オーナーとして、日本語または英語の基本UIで、登録、確認、検索、公開操作を理解したい。
- 受入観点:
  - ナビゲーション、入力項目、状態、エラー、安全警告の基本UIを日本語・英語で提供できる。
  - 原文、原文の言語、翻訳、言語非依存コードを同一の値として混在させない。
  - 翻訳がない投稿でも、原文の言語と未翻訳であることを識別できる。
  - 長い英語表現でも操作や警告が欠落しない画面設計へ展開できる。
  - 自動翻訳の提供は初期MVPの必須条件としない。

### US-OWN-010 自分のデータ権利を行使する

- 優先度・区分: RELEASE_GATE / 公開前対応
- ストーリー: オーナーとして、自分のデータを確認・出力し、必要に応じて訂正、削除、匿名化を求めたい。
- 受入観点:
  - 内部ユーザーID単位で、本人に関連する車両、非公開記録、共有候補、添付メタデータ、確認履歴を特定できる。
  - 本人のデータを機械可読な形式で出力できる境界がある。
  - 非公開の個人整備記録は原則削除できる。
  - 公開ナレッジは個人記録と分離され、削除、非公開化、関連解除、匿名化を区別できる。
  - 法的保全対象は通常削除と分け、人間の判断を経る。
  - 安全警告と同様に、データ出力・削除を有料機能にしない。

### US-OWN-011 危険・誤り・権利侵害を通報する

- 優先度・区分: RELEASE_GATE / 公開前対応
- ストーリー: 利用者として、公開事例に危険な情報、事実誤認、個人情報、権利侵害等を見つけたとき、対象を明確にして運営者へ通報したい。
- 受入観点:
  - 対象の共有ナレッジと通報理由を関連付けられる。
  - 安全上の緊急性、個人情報、権利侵害、その他の問題を区別できる。
  - 通報したことが投稿者や一般利用者へ不用意に公開されない。
  - 通報受付、確認中、対応済み等の状態を追跡できる。
  - 通報だけを理由に内容を自動削除せず、緊急非公開化を含む判断を人間が行う。
  - 通報手段を有料機能にしない。

## メカニック向けストーリー

### US-MEC-001 車種固有の事例を調べる

- 優先度・区分: P1 / 初期ベータ
- ストーリー: メカニックとして、入庫した車両に近い公開事例を車種、年式、仕様、症状、部品番号から探し、確認の手掛かりにしたい。
- 受入観点:
  - オーナー向け検索と同じ出典、確認状態、一致範囲、安全警告を確認できる。
  - MECHORYの情報だけで診断や作業結果を確定するよう促さない。
  - 公開ナレッジから、他ユーザーの非公開記録や個人情報へ遷移できない。
  - 初期ベータではメカニック専用の有料検索や顧客管理を要求しない。

### US-MEC-002 実際に確認した事例を提供する

- 優先度・区分: P1 / 初期ベータ
- ストーリー: メカニックとして、自分が提供する権利を持つ整備事例を構造化して提出し、車種別ナレッジへ貢献したい。
- 受入観点:
  - 顧客名、連絡先、ナンバープレート、VIN・車台番号全文等を入力・公開しない。
  - 実施した作業、確認した事実、原因候補、結果を区別できる。
  - 出典、許諾、確認者の区分を記録できる。
  - 運営確認を経るまで公開されない。
  - 資格・所属・専門性の確認が未完了の場合、「メカニック確認済み」と自動表示しない。
- 未確定: メカニック本人・資格・所属の確認方法、表示ラベルの付与基準。

### US-MEC-003 顧客車両と非公開事例を管理する

- 優先度・区分: LATER / 将来拡張
- ストーリー: メカニックとして、顧客の同意と適切な権限のもとで、複数の顧客車両と非公開事例を管理したい。
- 受入観点:
  - 初期MVPには含めない。
  - 顧客データ、代理操作、組織権限、データ処理契約、収益モデルを決定するまで実装しない。
  - オーナー向け個人記録の権限を流用して、暗黙に顧客データへアクセスさせない。

## 運営者向けストーリー

### US-OPS-001 公開候補を確認する

- 優先度・区分: P0 / 初期MVP
- ストーリー: 運営者として、ユーザーが明示的に提出した共有ナレッジ候補だけを確認し、公開、訂正依頼、見送りを判断したい。
- 受入観点:
  - 個人の非公開記録は通常の公開確認キューへ入らない。
  - 公開候補について、提出者、対象車両、出典、確認状態、危険領域、匿名化状態を確認できる。
  - 公開、訂正依頼、見送りを区別し、理由と日時を記録できる。
  - 運営者が内容を補完するために、架空の事例・部品番号・車両仕様を生成しない。
  - 管理者確認は正確性や安全性の保証ではないことを、表示設計で誤認させない。
- 未確定: 確認基準、担当者、対応時間、エスカレーション、見送り後の再申請方法。

### US-OPS-002 危険または不適切な情報を緊急非公開化する

- 優先度・区分: P0 / 初期MVP
- ストーリー: 運営者として、重大事故、権利侵害、個人情報漏えい等につながる可能性がある公開情報を、調査完了前でも一時的に非公開化したい。
- 受入観点:
  - 対象を公開停止状態へ変更し、通常の検索・閲覧対象から外せる。
  - 実行者、日時、理由、対象、変更前後の状態を記録できる。
  - 原文や個人情報を不要に複製せず、調査に必要な最小限の情報を扱う。
  - 非公開化、訂正、削除、法的保全を別の処理として扱える。
  - 復帰には再確認を必要とし、単なる再保存で自動公開されない。

### US-OPS-003 訂正・非公開化の申請を処理する

- 優先度・区分: RELEASE_GATE / 公開前対応
- ストーリー: 運営者として、ユーザーまたは第三者から届いた訂正・非公開化・権利侵害の申請を対象情報へ関連付け、対応状況を追跡したい。
- 受入観点:
  - 申請種別、対象、受領日時、状態、担当、判断、完了日時を追跡できる。
  - 安全上の緊急申請を通常申請と区別できる。
  - 法的要請は通常の訂正申請と区別し、自動開示しない。
  - 申請者の個人情報を公開投稿や一般ログへ出さない。
  - 具体的な受付窓口と対応期限は公開前に決定する。

### US-OPS-004 運営操作を監査する

- 優先度・区分: RELEASE_GATE / 公開前対応
- ストーリー: 運営者として、公開、訂正依頼、非公開化、削除、匿名化等の重要操作について、誰がいつ何をしたか確認したい。
- 受入観点:
  - 安定した内部識別子で、対象データと操作履歴を関連付けられる。
  - 操作種別、実行者、日時、理由、結果を記録できる。
  - 個人情報や本文全体を監査ログへ無制限に複製しない。
  - 監査ログの閲覧権限と保存期間を一般公開前に定める。
  - ログの存在だけで運営者へ非公開個人記録の無制限閲覧権限を与えない。

## 横断的な受入観点

- 初期値は安全側とし、非公開、未確認、未翻訳等の状態を公開・確認済みとして扱わない。
- 権限判定は画面表示だけに依存せず、Webと将来のExpoアプリで共有できる境界へ置く。
- 状態を色だけで区別せず、テキスト、アイコン、支援技術向けラベル等を併用する。
- 日本語・英語の文字量差で、重要操作、安全警告、エラー、確認状態が欠落しない。
- AI・OCRを使用しないローカルモックまたは手動フローでも、主要ストーリーを検証できる。
- 安全警告、基本検索、自分のデータ権利、通報・訂正手段を有料機能にしない。
- 外部サービス、課金、広告、決済、本番デプロイを、これらのストーリー定義だけを根拠に導入しない。

## 初期MVPの対象外

- AIによる故障診断、原因の断定、修理指示、安全保証
- 全世界の車種マスタとVINによる完全自動識別
- 紙・PDFの本番一括OCR、外部AIによる自動構造化、原本の恒久保存
- 自動翻訳と多言語横断検索の完全実装
- メカニックの資格認証、認証バッジ、顧客車両管理、有料相談
- 工場予約、部品販売、在庫連携、決済、広告SDK
- 汎用SNSタイムライン、フォロワー競争、リアルタイムチャット
- ネイティブアプリ、プッシュ通知、オフライン同期
- 完全な法務・モデレーション管理画面の自動化

## NEEDS_OWNER

- 初期ログイン方式と招待・復旧フロー
- FIAT Barchettaの仕様分類粒度
- 初期MVPで登録可能にする車両数
- 初期管理者の担当者、権限、確認基準、対応時間、エスカレーション
- メカニック確認済み表示を将来付与する際の本人・資格・所属確認方法

これらはユーザーストーリーの意図を変えない範囲で後続タスクに引き継ぎ、所有者承認前に実装仕様として確定しません。
