# ALPHA_PLAYBOOK

## 目的

最初の3〜5人へ遠隔で公開し、所有者が横にいなくてもMECHORIの基本体験を完了できるか確認します。αは集客や投稿量を増やす段階ではありません。致命的な分かりにくさ、データ消失、権限漏れ、公開範囲の誤解、診断サービスとの誤認を見つける段階です。

αの問題を直した後、`docs/BETA_PLAYBOOK.md`に従ってSNSでつながる10〜20人へ招待制βを広げます。

## 参加者

- 所有者と特に親しく、不具合や厳しい感想を率直に伝えられる3〜5人
- Web開発者だけに偏らせず、少なくとも1人はITサービスに詳しくない人を含める
- 可能なら車種、年式、DIY・工場整備の比率を分ける
- 実名、メールアドレス、SNSの友人一覧、連絡先はMECHORI側で追加収集しない

## αとβの違い

| 項目 | 遠隔α | 招待制β |
| --- | --- | --- |
| 人数 | 3〜5人 | 10〜20人 |
| 主目的 | 壊れていないか、意味が通じるか | 反復価値と車種横断の需要があるか |
| 募集 | 特に親しい友人へ個別依頼 | SNSでつながる知人へ個別依頼 |
| 観察 | 操作後すぐ聞き取り | 7日・30日再訪と紹介も確認 |
| 拡散 | 招待URLの転送を依頼しない | 上限内で個別招待を追加 |
| AI/OCR | 使用しない | 原則使用しない。別ゲートで判断 |

## αで提供する範囲

- Googleログイン
- 1人1つの期限付き招待URL
- メイン写真、任意のメーカー・車種、おおよその年式・所有開始時期による約3分の愛車登録
- 写真中心の愛車ページ、車齢・所有年月、短いコメント
- 写真と一言で残す出来事と、日常・整備をまとめた車両時間軸。初期値は非公開
- 明示的に最小項目だけを公開する愛車共有URLと公開停止
- 非公開の構造化整備記録と、参加中のαテスターへ文字情報および本人が別途確認した添付写真を共有できるGarage Journal
- 登録した愛車について、実車や手元の資料で分かるメーカー表記、車名、グレード、型式等を一項目から提案し、運営確認後に共有車両カタログを育てる協力体験
- DEMO公開事例によるナレッジ検索
- 自分の履歴表示、編集、データ出力
- アプリ内の公開範囲、通報、ミュート、ブロックの確認

実在する公開ナレッジ、AI回答、OCR、メール通知、決済、動画公開はαの対象外です。Journalの`公開`は一般公開ではなく、参加状態が有効なαテスター間だけの共有です。車両名、記録の本文、出来事の時期を非公開Workspaceとは別の最小共有データへ写します。添付写真は、本文の共有とは別に本人が確認した画像だけを非公開Storageへ保存して共有できます。動画、非公開の整備記録、添付資料、内部の車両IDは共有しません。公開をやめると共有データを削除し、他の参加者から写真を取得できない状態にします。

車両カタログへの協力は、知識量や入力件数を競わせる仕組みにしません。「全部を埋める」のではなく、本人が実車や資料から確かめられる一項目を持ち寄り、次に同じ車両を登録する人へ役立てる共同作業として案内します。提案数と反映数は本人の手応えとしてのみ表示し、ランキングや情報の正しさには使いません。利用者の提案は自動公開せず、運営確認前の候補であることを明示します。

愛車と簡易出来事の写真はブラウザ内で位置情報を引き継がない小容量WebP等へ再生成し、非公開保存します。Journalのα共有では、本人がナンバープレート、人物、住所を推測できる背景等を目視確認し、写真共有を別途選んだ再生成画像だけを扱います。共有URLには本人が目視確認し、明示的に公開した愛車メイン写真だけを含めます。整備記録PDF、車検証、明細原本、未確認のナンバープレート・顔・住所・正確な保管場所はαへアップロードしません。

## 必要な外部基盤

### α開始時に必要

- Supabase Free: Google認証、Postgres、RLS、必要最小限のStorage
- Google CloudのOAuth設定: Supabase AuthのGoogleログインだけに使用
- Netlify Free: α用URLとNext.js配信

Google OAuthをテストモードで使う間は、MECHORIの招待URLを発行する前後に、所有者が相手のGoogleアカウントをGoogle Auth Platformのテストユーザーへ追加します。Google OAuthを`本番環境`へ公開した後はこの作業を省略できますが、MECHORIの1人用招待と参加権限は維持します。3〜5人への具体的な手順と依頼文は`docs/ALPHA_LAUNCH_CHECKLIST.md`に固定します。

### α開始時には不要

- OpenAI API
- Resend
- Sentry
- Apple Developer Program
- X、Facebook等のログインProvider
- 独自ドメインの本番接続

αは`mechori.com`の一般公開ではなく、α用の検証環境として分離します。外部アカウント作成、接続、秘密情報入力、デプロイは、所有者が各手順を確認して承認した後に行います。

## 招待の安全条件

- 招待URLは1人につき1つ発行し、標準の利用上限を1人とする
- URL中の生トークンをDB、ログ、分析イベントへ保存しない
- 生トークンはURLフラグメントで渡し、取得直後にアドレス欄から除去する
- DBには十分にランダムなトークンのハッシュだけを保存する
- 有効期限、失効日時、使用者、使用日時を保持する
- 同じ利用者の再ログインは新しい利用として数えない
- 使用済みURLを別アカウントが再利用できないようにする
- 所有者が1件ずつ失効でき、α全体も停止できるようにする
- 認証済みでもα参加権限がなければアプリの非公開領域へ入れない
- 参加済みユーザーはMECHORI内の`招待`から7日間・1人用URLを発行できる
- 参加者1人あたり未使用3件、直近30日10件を上限とし、無制限な拡散を防ぐ
- URLコピー、OSの共有画面、端末内生成のQRコードを選べる
- QR生成のために招待URLを外部サービスへ送信しない

## 公開前の必須確認

- Googleログイン後、招待を使用した本人だけが自分の非公開領域へ入れる
- RLSテストで、別利用者の車両、整備記録、Journal、下書き、メディアを読めない・変更できない
- テスターAが共有したJournalの文字情報と、写真共有を別途確認した画像だけがテスターBのフィードへ表示される
- 写真共有を確認していない画像、動画、非公開整備記録、内部IDはテスターBへ表示されない
- Journalの共有停止後、テスターBは以前のα共有写真を再取得できない
- 未ログイン利用者と参加停止中の利用者は、αテスター向けJournal共有データを読めない
- 未ログイン利用者は公開DEMO以外へ入れない
- 招待の期限切れ、失効、使用済み、再ログインを確認できる
- ブラウザ更新、ログアウト、再ログイン後も保存内容を失わない
- 自分のデータを書き出せる
- 所有者が参加者の無効化とデータ削除依頼を処理できる
- バックアップ方法と復元手順を確認する
- 写真共有を確認していない画像を含む投稿が誤って共有されない
- αであること、DEMOと実データの違い、診断・修理指示ではないことを画面で確認できる
- スマートフォンの主要ブラウザで登録から記録保存まで完了できる
- 未登録者が共有URLを開いても、非公開Workspaceへアクセスできず、公開用の最小項目だけを閲覧できる

## 日本語レビュー

α前に、ホーム、ログイン、愛車登録、登録完了、最初の出来事、愛車時間軸、共有、整備記録、検索、公開範囲、エラーの順で全文言を確認します。

- 一読して意味が通り、主語と対象が曖昧でない
- 直訳調、二重否定、抽象的な比喩を避ける
- ボタンは押した後に起きることを表す
- 「原因」「確認済み」「公開」等を、実際の状態より強く言わない
- 空結果は「見つからなかった」と明示し、検索範囲やAIの能力を誇張しない
- 「端末内」「サーバー保存」「公開」「運営確認待ち」を混同しない
- 同じ概念は`docs/GLOSSARY_JA_EN.md`と同じ語を使う

不自然な文言はαテスターへ評価を委ねず、公開前に可能な限り修正します。αでは、開発者には自然に見えても利用者が誤解した表現を追加で発見します。

## テスターへ依頼する操作

1. 個別の招待URLを開き、Googleでログインする
2. 自分の愛車写真を1枚選び、候補にない場合も自由入力して約3分で愛車ページを作る
3. 写真または一言で、納車、今日の一枚、ドライブ等の出来事を1件だけ非公開保存する
4. もう1件は`α参加者に公開`を選び、写真共有を選ばない場合は文字情報だけが、写真共有も選んだ場合は確認した写真も別の参加者のフィードへ表示されることを確認する
5. 愛車の時間軸が増えたことを確認し、共有ページのプレビューと公開項目を確認する
6. 実車または手元の資料で確認できる車両情報があれば、一項目だけカタログへ提案し、元の愛車表示が勝手に変わらないことを確認する
7. 個人情報を含まない範囲で、過去の整備記録を1件だけ非公開保存し、編集・履歴表示を行う。正確な日付を覚えていない場合は、年月ごろ・年ごろ・時期不明のまま保存する
8. DEMOのナレッジ検索を行い、何の画面だと思ったか回答する
9. 一度ログアウトし、同じGoogleアカウントで戻れるか確認する
10. その場で詰まった箇所と、もう一度使う場面があるかを伝える

操作手順を先に細かく説明しません。安全上の禁止事項とテストデータの範囲だけを伝え、どこで迷うかを確認します。

## フィードバック

初回は15〜30分を目安に、利用直後に通話または普段の連絡手段で聞き取ります。MECHORIからSNSのDMを自動送信せず、連絡先も取り込みません。

ログイン後の上部にある`感想`から、良かった、迷った、動かなかった、欲しい、その他のいずれかと自由記述をMECHORI内へ送信できます。メールアドレスの入力やメールアプリは不要です。送信内容は本人と運営だけが扱い、運営は`/admin`で状態と運営メモを管理します。短時間の連続送信はDB側で制限します。

- 最初に何のサービスだと思ったか
- 愛車プロフィールだけのサービスと何が違うと思ったか
- 困ったとき、一般検索とは別にMECHORIを開く場面を想像できたか
- 登録前に不安だったこと
- 車種を迷わず登録できたか
- 愛車ページが完成したとき、少しでも嬉しい・続きを追加したい・見せたいと感じたか
- 整備記録とJournalの違いが分かったか
- 検索を故障診断だと思わなかったか
- 日本語として引っかかった箇所
- 保存されたか不安になった箇所
- 他人に見えると思った情報
- 次に開くとすれば、いつ、何のためか
- 使わないとすれば最大の理由は何か

## α終了条件

- 3人以上が、所有者の操作代行なしでログイン、写真付き愛車登録、最初の非公開出来事、α参加者向け投稿、愛車時間軸の確認を完了した
- 2人以上が、完成した愛車ページを見せたい、共有したい、または過去の記録を追加したいと自発的に回答した
- 利用者間のデータ漏れ、重大なデータ消失、意図しない公開が0件
- 検索を診断・修理指示と受け取る重大な誤解が0件
- 主要操作を止める不自然な日本語または説明不足が解消された
- 2人以上が、催促ではなく自分の目的で7〜14日以内に再訪した、または再訪しない具体的理由を把握できた
- 招待失効、参加停止、データ出力・削除依頼を所有者が処理できた
- βで検証する仮説と、βへ持ち越さない重大問題を分けられた

人数を増やせば解決する問題ではないため、条件を満たさない場合はβ募集を始めず、初回体験または権限制御を修正します。
